# 스타일 안(색·글씨체·글자 위계) 비교·적용 — 설계 명세 (2026-10-26)

상태: **구현 완료(2026-10-26)** — 계획과 다르게 정한 4가지는 아래 '구현 메모'
관련: `docs/다이어그램탭_개선점_및_카드보드_설계안.md` 6부(참고삽도 분류), 시안 `docs/스타일안_시안/안3종_비교_시안.png`

## 1. 목적과 성공 기준

사용자 요구(2026-10-26): 다이어그램의 **색과 글자 크기 위계가 참고삽도를 따르길** 원하고, **다 만든 뒤에** 색·글씨체 안을 여러 개 놓고 **비교해 보며 골라 적용**하고 싶다. (만들 때 고르는 것이 아님.)

성공 기준
- 결과(또는 페이지)가 나온 뒤 버튼 하나로 안 3개를 같은 그림으로 나란히 보고, 하나를 눌러 적용·되돌리기가 된다.
- AI 호출 없이 즉시(1초 안팎) 보인다.
- 적용해도 그림 구조·내가 손으로 고친 내용(위치·글자·직접 칠한 색)이 깨지지 않는다.
- 예전에 만든 결과(버블도·조닝도 포함)와 모든 종류에 같은 방식으로 먹는다.

범위 확정(사용자): **전체에 한 번에**(페이지 모드의 모든 칸 + 단독 결과). 칸마다 따로 적용하는 기능은 만들지 않는다.
방식 확정(사용자): **C 단계별 혼합** — 1단계는 색 바꿔 끼우기 + 글씨체 + 제목 배율, 2단계는 어색한 종류만 렌더러가 안의 값을 직접 읽도록 이전.

## 2. 참고삽도에서 읽은 값 (근거)

읽는 방법: A·D·E 는 PDF 글자층(글꼴·크기·색), 색은 A~F 쪽을 낮은 해상도로 그려 채도 높은 픽셀을 모은 근사값. B·C·F 는 이미지 PDF 라 글꼴은 못 읽음(D·E·F 는 같은 틀이라 같을 가능성). 프로젝트명은 적지 않는다(사내 자료).

| 항목 | 읽은 값 |
|---|---|
| 글꼴 | A: Freesentation 계열. D·E: Pretendard 본문 + 제목용 굵은 고딕(HY견고딕·공고딕 계열) |
| 글자 위계 | 본문 1배 기준: 쪽 큰 제목 약 2.5~3.6배(굵게), 소제목 약 1.7~2배. 앱의 쪽 설정(`page.js` `recommendType`: 32/18/11/8pt)은 2.9 : 1.6 : 1 로 이미 거의 같다 |
| 글자색 | 거의 먹색(`#231F20`·`#231815`)과 검정. 흰 글자는 색 띠 위에서만 |
| 진한 포인트 | 주황 `#EE9E3C`(D) `#F69D3B`(E) `#E1962E`(F) `#F57A35`(B) `#F6873D`(C) `#DFA837`(A) · 청록 `#2B99BC`(D) `#27A0C8`(E) · 파랑 `#2F4E9A`(A) · 초록 `#6CAA43`(D) `#5C9F36`(F) `#9DBA25`(C) |
| 옅은 면 | 주황 `#F5D4B4`~`#FADBBA`(전 건 공통, 가장 흔함) · 청색 `#B3D6ED` `#A9DAE9` `#99BFE6` · 초록 `#D3E3B2` `#D4E4B6` · 분홍 `#F1B7BC` |
| 면 비율 | 쪽 전체에서 채도 높은 면은 1~2% 이하. 바탕은 흰색·회색 |

현재 앱: 주황 `#F28C28`, 파랑 `#1E90C8`(배치)·`#2F7FBF`(매스)·`#2F6BB5`(카드), 초록 `#3E8E41`·`#2F6B4F`(개요표). 같은 역할의 색이 렌더러마다 조금씩 달라 한 번에 바꿀 장치가 없다.

## 3. 사용 흐름

1. 결과가 있을 때 도구 줄에 **"스타일 안 비교"** 버튼.
2. 누르면 창이 열리고 안 3개가 같은 그림(페이지 모드면 페이지 전체 축소본)으로 나란히 놓인다. 각 안 카드에는 이름 · 색 칩 4개(포인트 3 + 글자색) · 글씨체 이름(이 PC에 없는 글꼴이면 "이 PC에 없어 대체 글꼴" 표시). 지금 적용 중인 안에는 표시.
3. 카드를 누르면 바로 적용되고 창 뒤의 그림도 바뀐다(다른 카드를 눌러 바꿔 볼 수 있음). **"지금 모습"** 카드 = 원래대로.
4. 적용된 안은 결과와 함께 저장돼 다시 열어도 유지된다.

## 4. 안의 데이터

```
THEME = { id, label, source,        // source: 어느 참고삽도 건에서 뽑았는지(A~F)
          a1, a2, a3,               // 포인트 3색(주황 역할 / 청·청록 역할 / 초록 역할)
          ink,                      // 아주 어두운 글자·선 색
          fontId,                   // fonts.js 의 TEXT_FONTS id
          titleK }                  // 쪽 제목·칸 제목 크기 배율(기본 1)
```

1단계 안 3개(2026-10-26 사용자 결정: 5개 시안에서 지금 모습 · A형 · 먹색 정돈형만 남김). 색은 시안에서 확인한 값:

| id | 이름 | a1 | a2 | a3 | ink | 글씨체 |
|---|---|---|---|---|---|---|
| `current` | 지금 모습 | — | — | — | — | 맑은 고딕(지금 그대로) |
| `blue` | 참고 A형 — 파랑 중심 | `#DFA837` | `#2F4E9A` | `#7BA23A` | `#231815` | Pretendard (참고 A 의 Freesentation 은 §9, 사내 보드 기본 글꼴과 같은 계열) |
| `mono` | 먹색 정돈형 — 포인트 하나 | `#E8832A` | `#5F6670` | `#8A9097` | `#1F2328` | Noto Sans KR |

`titleK`: `current` 1, `blue` 1.1(참고 A 의 큰 제목 위계), `mono` 1. (실제 값은 구현 중 눈으로 보고 조정.)
안을 더 늘리는 것은 나중에 `THEMES` 목록에 항목을 더하면 된다(코드 구조는 안 개수와 무관). 참고 D·E·F형(주황·청록), B·C형(주황·초록) 시안은 빼기로 했다 — 시안 이미지는 `docs/스타일안_시안/안3종_비교_시안.png` 에 3개만 남긴다.

## 5. 적용 방식 (1단계)

### 5.1 색 바꿔 끼우기 `applyTheme(svg, themeId)` — 새 파일 `src/conceptDiagram/theme.js`
순수 함수(문자열 → 문자열). 그림 SVG 의 `fill` `stroke` `stop-color` `flood-color` 속성과 `style` 안의 `#RRGGBB` 만 바꾼다(그림 데이터·id·url 참조는 건드리지 않음).
- 색을 HSL 로 보고 **계열**로 나눈다: 색상 15~70° = a1(주황·노랑·갈색), 70~165° = a3(초록), 165~255° = a2(청록·파랑). 나머지(빨강·보라·분홍)와 채도 0.15 미만 무채색은 그대로.
- 계열 안에서는 앱의 기준색(주황 `#F28C28`, 파랑 `#1E90C8`, 초록 `#3E8E41`)과의 **명도 차이를 유지**하고, 채도는 비율로 옮긴다 → 진한 색은 안의 진한 색, 옅은 면은 안의 옅은 면이 된다.
- 무채색 중 명도 0.2 미만(글자·선의 먹색)은 안의 `ink` 로, 그 위 회색 계열은 그대로.
- `mono` 는 a2·a3 가 회색이라 포인트 하나만 색이 남는다.
- 시안은 이 알고리즘의 시제품(버리는 코드, 스크래치 `proto_theme.mjs`)으로 만들었다. 색 속성만 바꾸므로 구조는 그대로이고, 4종 그림 모두 눈으로 깨짐이 없음을 확인했다(구조 지문 같음은 §8 시험으로 확인할 일).

### 5.2 끼우는 자리와 불변식
기존 흐름 `renderSpec → (applyEdits) → 화면/페이지` 에서 **`renderSpec` 직후, `applyEdits` 직전**에 끼운다(`ConceptDiagram.jsx` 의 렌더 지점 2곳: 결과 그림, 페이지 칸 조립). 손스케치(`type: 'sketch'`)는 `renderSketch` 직후(글꼴 바꿈과 같은 자리).
- **항상 새로 그린 SVG 에서 시작**한다(이미 안이 입혀진 SVG 에 다시 입히지 않음) → 안을 몇 번 바꿔도 색이 누적되지 않는다.
- 구조 지문(`scanSvg().sig`)은 요소 종류만으로 정해져 색 변경에 영향이 없다 → 손으로 고친 내용(`edits`)은 그대로 유효하고, 사용자가 직접 칠한 색은 `applyEdits` 가 안 위에 덮어 **보존**된다.
- 구조형 편집기(`SvgEditor`)가 받는 `baseSvg` 도 안이 입혀진 SVG 여야 화면에서 보는 색과 편집이 일치한다.
- 손스케치 편집기(`SketchEditor`)가 스스로 부르는 `renderSketch` 도 같은 안을 받아야 편집 화면 색이 결과 화면과 같다.

### 5.3 글씨체·제목 배율
- 글씨체: 안의 `fontId` 를 쪽의 글꼴로 설정(기존 `ENGINE_FONT` 바꿔 끼우기 사용, 사용자가 쪽 설정에서 따로 고르면 그것이 우선).
- 제목 배율: `composePage` 의 제목·칸 제목 크기에 `titleK` 를 곱한다(위계 경고 계산에도 반영).
- 쪽이 직접 그리는 글자·선 색(제목 `#1f242b`, 칸 제목, 설명 `#555a60`, 구분선 `#8a9099` 등)은 `composePage` 에 `theme` 옵션을 받아 같은 규칙(ink·무채색)으로 바꾼다. 칸 안 그림은 5.2 에서 이미 입혀졌으므로 쪽 조립 단계에서 다시 입히지 않는다.

### 5.4 저장
- 안 id 를 `result.theme`(단독 결과)와 쪽 상태(페이지 모드, 기존 쪽 설정이 저장되는 곳)에 둔다. 값이 없으면 `current`.
- 안 정의(색표)는 코드에 있고 저장은 id 만 → 나중에 색을 다듬어도 예전 결과가 따라간다.

### 5.5 비교 창
- 썸네일은 **지금 그린 SVG 를 안마다 `applyTheme` 한 문자열**로 만든다(AI·재그리기 없음). 페이지 모드는 칸 SVG 에 안을 입힌 뒤 `composePage` 로 쪽 하나를 조립해 축소 표시.
- 카드 3장 × 쪽 조립 3회가 1초 안에 끝나는지는 구현 때 측정하고, 느리면 썸네일을 작은 크기로만 조립한다.

## 6. 하지 않는 것
- 안마다 그림 속 글자 크기를 다시 정하지 않는다(그림 속 글자는 렌더러 크기 그대로, 쪽에서 본문 pt 에 맞춤).
- AI 가 안을 지어 주지 않는다. 안은 코드에 든 3개뿐.
- 칸마다 다른 안, 사용자 정의 안(색 직접 입력)은 이번에 만들지 않는다.
- 사진·래스터 이미지(내 이미지)의 색은 바꾸지 않는다. 조감도 탭과 무관.
- 글꼴 파일을 앱에 넣는 일(§9).

## 7. 한계와 위험
- **손스케치 계열**: 스펙 안의 색 값(사용자가 고른 색 포함)이 그려진 뒤에 바뀌므로, 사용자가 직접 정한 색도 같은 계열이면 같이 바뀐다(구조형 결과는 `edits` 가 안 위에 덮여 보존됨).
- **계열 분류**: 갈색(주황 계열, 채도 낮음)·노랑이 a1 로 가고 연두는 a3 로 간다. 의도와 다르게 보이는 색이 있으면 §5.1 의 구간을 조정한다.
- **글씨체**: Pretendard 는 앱 내장이라 화면·PNG 는 문제없고(저장한 SVG 는 설치 필요), Noto Sans KR 은 PC 에 따라 대체 글꼴로 보일 수 있다.
- **어색한 종류**: 카드 보드는 대부분 회색 면이라 안의 차이가 작다. 이런 종류는 2단계에서 렌더러가 안의 값을 직접 읽게 한다.
- **대비**: 안 색이 흰 바탕·옅은 면 위에서 읽히는지 시험으로 확인한다.

## 8. 시험 계획
회귀 점검(`scripts/regression/check_diagrams.mjs`)에 추가.
1. `current` 는 입력과 완전히 같다(변화 없음).
2. 기준색 3종이 각각 안의 a1·a2·a3 로 가고, 무채색 회색·흰색은 그대로이며 먹색은 `ink`.
3. 같은 SVG 에 안을 입혀도 요소 수·구조 지문이 같다.
4. 이미지 데이터 URI·`url(#id)`·`marker` 참조는 변하지 않는다.
5. 예시 스펙 전체(종류별) × 안 3개를 그려 오류·NaN 없음.
6. `applyEdits` 로 덮은 색은 안을 바꿔도 유지된다.
7. 안 ink 와 흰 바탕의 명암비 ≥ 4.5.
8. 페이지 조립에 `theme` 를 주면 제목·칸 제목 색이 `ink` 로 바뀌고 `titleK` 가 크기에 반영된다.
화면 시험: 비교 창 열기·적용·되돌리기·다시 열기(저장 복원)를 테스트 화면(하니스)에서 확인.

## 9. 열린 질문 (구현 전에 정할 것)
- **Freesentation(참고 A 의 글꼴)** 을 목록에 넣을지: 설치 안 된 PC 에서 보이지 않으며, 앱에 글꼴 파일을 함께 넣으려면 라이선스 확인이 필요하다(확인 전 미정). 지금은 같은 계열인 Pretendard 로 둔다.
- 안 이름·색 칩의 최종 값: 구현 뒤 화면에서 보고 사용자가 확인한다.
- **Pretendard 는 앱 화면(UI)에는 내장**(`public/fonts`, SIL OFL)이지만, **그림(SVG 이미지)은 시스템에 설치된 글꼴만** 쓴다 → 쪽 미리보기·비교 창 썸네일·PNG·저장한 SVG 는 그 PC 에 설치돼 있어야 Pretendard 로 보인다(2026-10-26 브라우저에서 직접 확인: 이 PC 는 설치 안 됨). 앞서 '화면·PNG 는 내장이라 보인다'고 적은 것은 틀렸다. Noto Sans KR 은 내장이 아니므로 PC 에 따라 대체 글꼴로 보일 수 있다 → 안 카드에 설치 여부를 알려 준다(`document.fonts.check`). 맑은 고딕은 Windows 기본.

## 10. 단계
- **1단계(이번)**: `theme.js`(안 3개 + `applyTheme`), 렌더 지점 3곳 연결, 쪽 조립의 `theme` 옵션, 비교 창, 저장, 시험.
- **2단계(나중, 사용자가 어색하다고 한 종류만)**: 해당 렌더러가 안의 역할 색을 직접 읽도록 이전.

## 구현 메모 (2026-10-26, 명세와 달라진 점)
- 안 id 는 결과별(`result.theme`)이 아니라 **쪽 설정 `pg.theme` 한 곳**(단독 결과에도 같은 값). `cd_page_v1` 에 같이 저장된다.
- 무채색 판정: **채도 < 0.15 이거나 (명도 < 0.3 이고 채도 < 0.35)** 를 무채색으로 본다(어두운 청회색 글자색이 청색 계열로 가는 것을 막음). 명도 < 0.2 인 무채색만 안의 ink 로 간다.
- '지금 모습'은 글씨체를 건드리지 않는다(새 쪽의 기본 글씨체는 Pretendard 이므로 명세 표의 '맑은 고딕'은 틀렸음).
- 글꼴 설치 확인은 `document.fonts.check` 가 아니라 캔버스 글자 폭 비교(`fontcheck.js`).
- 검토(독립 검토자) 반영: 거의 흰 옅은 색은 무채색으로 보고(채도<0.5 이고 명도>0.93), 명도는 기준색→안의 색, 0→0·1→1 구간 선형 대응으로 옮긴다(옅은 면이 흰색으로 쏠리지 않게). 손스케치 편집 화면의 선택 틀·회전 손잡이·강조선(주황)은 `data-ui` 표시를 붙여 안을 입히지 않는다. 비교 창이 열려 있는 동안 뒤 화면의 단축키(방향키·Delete·Esc·Ctrl+S 등)는 막고, 창은 `role="dialog"`·초점 가두기·초점 복원을 갖는다. 글꼴 확인은 SVG 이미지에서 실제로 먹는지 픽셀로 비교한다(`fontRendersInSvgImage`).
