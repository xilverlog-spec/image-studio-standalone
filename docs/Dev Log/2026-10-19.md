## 2. 출력 크기 · 칸 나누기 · 글자 위계 (사용자 요청: 다이어그램 사이즈를 정하고, 글자 위계(pt)·글씨체를 추천받고, 한 페이지를 칸으로 나눠 칸 하나를 골라 그 크기에 맞게 만들기)

## 3. 칸 직접 끌어서 크기 조절 + 바깥 여백·테두리선 (사용자 요청)
- 요청: 칸을 나눈 뒤 그림에서 직접 사각형을 움직여 크기를 조절, 겉 가장자리 테두리 간격도 설정.
- 배치 데이터: 칸마다 `{ id, r:[왼쪽,위,오른쪽,아래] }`(페이지 안쪽 영역 대비 0~1). 프리셋을 끌면 모양을 복사해 `layoutId:'custom'` + `pg.custom` 이 되고(`basePreset` 에 처음 프리셋을 기억해 '배치 되돌리기'), 칸 번호(id)는 끌기·나누기·삭제에도 유지돼 칸의 그림이 따라간다(`getCells`·`normalizeCustom`·`presetToCustom`, 최대 12칸).
- 끌기 계산(순수 함수, page.js): `dragEdge`(가장자리 하나. group=기본이면 같은 선에 맞닿은 칸의 가장자리도 함께 → 경계선 끌기, Alt 면 그 칸만; 최소 25mm, 가운데·다른 칸·바깥 가장자리에 3mm 안쪽이면 붙음), `dragMove`(칸 옮기기, 바깥 못 나감, 붙기), `setCellMm`(mm 입력), `splitCell`(좌우/위아래 반으로, 새 id), `removeCell`, `overlappingCells`.
- 화면: 미리보기의 칸 위에 투명 덮개(칸 고르기·몸통 끌어 옮기기)와 고른 칸의 8개 점(크기 조절). 끄는 동안은 가벼운 윤곽선과 크기(mm) 표시만 하고 손을 떼면 한 번만 다시 그림(끌 때마다 그림·이미지를 다시 그리면 느려서). window 의 pointermove/up 으로 처리해 칸 밖으로 나가도 이어짐. PageBox: 고른 칸 X·Y·가로·세로(mm), 나누기·삭제·배치 되돌리기.
- 바깥 여백: `composePage` 의 `margin`(null=자동 인쇄 8mm·화면 6mm 이상, 짧은 변의 4% / 숫자 한 값 / {t,b,l,r}), 빈 칸은 자동, 0 허용, 한 변은 용지의 30%까지, 위·아래/왼쪽·오른쪽 여백이 커서 그림 자리가 반 미만이면 경고. 제목·소제목은 왼쪽 여백에서 시작하고 폭도 좌우 여백을 뺀다. 테두리선 `frame`(굵기 pt→mm, 간격 mm 비우면 가장 작은 여백의 절반, 색). 화면: '자동' 옆에 자동값(mm) 표시, 직접 입력으로 바꾸면 현재 값으로 시작, '네 변 같게'.
- 시험: check_diagrams 152개(새로 28개: 끌기 6종(경계선 4칸 동시·Alt 한 칸·최소 크기·가운데에 붙기·L자 배치·세로 방향)·겹침 없음·옮기기·mm 입력·나누기·삭제·12칸 한도·custom 정리·mm 크기(raw)·custom 배치 조립, 여백 자동/한 값/변마다/0·빈 칸·30% 제한·제목 위치·테두리선(기본 간격·지정·끄면 없음)·경고), 실제 앱 화면 부품에서 포인터 이벤트로 2×2 의 가운데 경계선을 100px 끌기(195→234/156mm 네 칸 동시, '직접 조정한 배치'로 전환, 끄는 동안 크기 표시), Alt 끌기(한 칸만), mm 입력(150), 나누기(5칸), 삭제, 배치 되돌리기(2×2 복귀), 여백 자동→직접→네 변 같게→따로, 테두리선 기본 간격 7.5mm 확인.
- 한계: 칸을 삭제해도 비운 자리는 이웃에 합쳐지지 않음, 칸 겹침을 막지는 않고 알리기만(Alt 끌기·옮기기), 끄는 동안 그림은 갱신되지 않음(윤곽선만), 터치 화면은 시험하지 못함, 모니터가 작은 창에서 점이 작게 느껴질 수 있음(11px).

## 4. 단축키 + 글자 위계 안전장치 (사용자 요청: 기본적인 단축키 / "이거 정확히 어떤 위계인지 설명해줘" — 제목이 작고 소제목이 큰 화면)
- 단축키(ConceptDiagram 창 전체 keydown, 이 탭이 안 보이면 무시, 입력칸에 글자 입력 중에는 Ctrl+Enter·Ctrl+S 만): Ctrl+Z/Y(Ctrl+Shift+Z) 페이지 되돌리기·다시 하기, Delete 칸 비우기(Shift 칸 삭제), 방향키 이동 1mm(Shift 10)·Alt 크기, Tab/Shift+Tab 칸 이동, Esc 끌기 취소, Ctrl+C/V/D 칸 내용 복사·붙여넣기·빈 칸에 복제, Ctrl+S/Ctrl+Shift+S 저장, Ctrl+Enter 만들기.
- 페이지 되돌리기 기록: 칸 배치(layoutId·custom·basePreset)·칸 안 결과(cells)·고른 칸을 스냅샷으로 60단계까지, 같은 종류의 연속 동작(방향키·mm 입력)은 0.8초 안이면 한 번으로 묶음. 새 그림이 칸에 들어갈 때만 기록(type 또는 ver 가 바뀔 때; 모든 결과에 ver 를 달았음), 같은 그림을 고치는 것은 편집기가 기록. 칸 배치 선택(프리셋·격자)도 기록.
- 손스케치 편집기와의 충돌 방지: 편집기도 창 전체에서 Ctrl+Z/C/V/D·Delete·방향키를 받으므로, 마지막에 만진 곳(`ctxRef`: 페이지 미리보기·설정 상자='page', 편집기='sketch')을 기록하고 편집기는 `shortcutsEnabled()` 가 false 일 때(page 를 만진 직후) 키를 무시.
- 글자 위계: 표준 용지 추천값은 항상 제목>소제목>본문>작은 글자(A3 32/18/11/8, A4 23/13/8/6, A1 64/36/22/16, PPT 36/22/14/11). 빈틈 두 가지를 고침: ① 직접 넣은 pt 가 거꾸로(제목 6·소제목 40)여도 경고 없이 따르던 것 → 빨간 경고 추가(제목>소제목, 소제목>본문, 본문>작은 글자 점검) ② 아주 작은 직접 입력 용지(예: 42×29.7mm)에서 본문 바닥값(7pt) 때문에 제목 3pt < 본문 7pt 로 뒤집히던 것 → 바닥값으로 본문이 올라가면 소제목(본문×1.3 이상)·제목(소제목×1.4 이상)도 올림.
- 시험: check_diagrams 158개(위계 6개 추가), 실제 앱 화면 부품에서 키 이벤트로 끌기→Ctrl+Z(2×1 복귀)→Ctrl+Y(custom), Delete→Ctrl+Z, 방향키(x +1·+10, Alt 로 가로 +1), Tab/Shift+Tab 확인.

## 5. 그림 속 글자를 본문 목표 pt 에 맞춰 넣기 (사용자 지적: 칸에 넣으면 그림 속 글자가 23pt 로 소제목(18pt)보다 커져 위계가 깨짐)
- 원인: 그림 속 글자 크기는 렌더러가 정한 px 이고 칸에 맞추는 배율 s 가 그대로 곱해져, 큰 칸에 작게 그려진 그림은 글자가 커짐(경고만 하고 안 고침).
- 구현: `scaleTexts(svg, k)` — 렌더러 SVG 의 `<text font-size y>` 를 직접 고쳐 글자 크기만 k 배(그림·도형은 그대로), 글자 가운데 위치를 지키도록 기준선 `y' = y − 0.35·fs·(1−k)`, 글자 둘레 흰 테두리(stroke-width)도 같은 비율, 회전·dy·baseline·textLength 글자는 제외. `composePage` 에 `fit` 모드: `fill`(칸 꽉 채움, 글자는 그림 배율 따름, 기존·시험용 기본) / `text`(본문 글자를 목표 pt 에 맞추기, 그림을 줄임) / **`both`(칸 꽉 채우고 글자만 목표 pt, 앱 기본)**. `both` 의 글자 배율 k = 목표 pt·0.3528 ÷ (그림 배율 s × 원래 본문 크기), 1.3배(키울 때 칸 밖으로 넘침)~0.3배로 제한. 그림 속 글자끼리 비율(소제목급·본문·작은 글자)은 유지. 보고에 `textScale`.
- 화면: 📐 상자 '그림·글자 맞춤' 세 가지(권장 both 기본) + 설명, `pg.fit`(옛 `pg.fill` 은 쓰지 않음).
- 시험: check_diagrams 169개(새 11개: scaleTexts 기준선·테두리·제외 글자·배율 1, 큰 칸에서 fill 은 본문이 목표보다 큼 / both 는 같은 배율에서 본문이 목표 pt·위계 경고 없음·글자 배율 공식·0.3~1.3 제한), 실제 앱 화면에서 기본 both·'지금 결과 11pt' 확인, 층별 조닝 예시를 Edge 로 fill(층 이름 15.2pt) 대 both(11pt) 비교.
- 한계: 사진·AI 이미지 편집 결과에 박힌 글자는 그림 일부라 못 바꿈. 글자를 키워야 하는 경우(k>1)는 칸 안에서 겹칠 수 있어 1.3배까지만. 글자를 줄이면 라벨이 박스 안에서 상대적으로 작아 보일 수 있음.

## 6. "다이어그램 수정하는 페이지가 없어졌다" → 페이지 모드에서 편집기가 화면 아래로 밀려 있었음
- 원인(시험 페이지로 재현): 페이지 모드에서는 오른쪽 위에 페이지 미리보기(약 768px)가 먼저 놓이고 손스케치 편집기가 그 아래(864px, 보이는 영역 893px 의 맨 끝)에 놓여 스크롤을 내려야만 보였다. 게다가 페이지 모드 켬 여부를 localStorage 에 기억해 다음에 열어도 켜진 채 시작 → 켠 것을 잊으면 편집기가 없어진 것처럼 보임. 페이지 모드를 끈 일반 상태에서는 편집기가 맨 위(81px)에 정상.
- 수정: ① 페이지 모드는 기억하지 않고 항상 꺼진 채로 시작(설정만 기억) ② 오른쪽 위 전환 버튼 [📄 페이지 배치·칸 크기 조절] / [✏️ 선택한 칸 편집](손스케치 결과일 때) + [페이지 모드 끄기], 한 번에 한 화면만 보임 ③ 새로 만든 손스케치류 결과(생성·AI 이미지 편집)는 자동으로 편집 화면, 페이지 모드를 켤 때는 페이지 배치 화면 ④ 칸 더블클릭 = 그 칸 편집 ⑤ 화면을 바꾸면 단축키 받는 쪽도 같이 바뀜(편집=손스케치 편집기, 페이지=페이지 단축키).
- 시험(실제 앱 화면 부품 + 가짜 서버): 끈 상태 편집기 맨 위, 켜면 전환 버튼 3개·페이지 화면, 편집 전환(편집기 153px·칸 크기 안내 문구), 되돌아가기, 칸 더블클릭, 끄기(편집기 81px 복귀), 페이지 화면에서 새로 만들면 편집 화면으로 자동 전환, 편집 화면의 Ctrl+Z 는 편집기가 받고 페이지 안내 알림이 안 뜸.
- 확인 못 한 것: 실제 앱(프로젝트 비밀번호 필요)에는 들어가지 못해 같은 화면 부품으로 시험함.

## 7. 그림 위에서 글자를 바로 클릭해 고치기 (사용자 요청)
- 배경: 손스케치류는 오른쪽 패널에서, 그 밖의 결과(배치 개념도·평면 다이어그램·매스 과정도·층별 조닝도·버블도)는 그림이 `<img>` 라서 왼쪽 "글자 수정" 목록에서만 고칠 수 있었다.
- 구현: `src/InlineText.jsx` — `textAtPoint`(화면 좌표가 놓인 `<text>`, pointer-events 가 꺼진 글자도 찾음), `InlineInput`(글자 위에 겹쳐 열리는 입력칸: Enter 확정·Esc 취소·바깥을 누르면 확정, 키 이벤트는 stopPropagation 으로 단축키가 새지 않게), `InlineSvgView`(그림을 인라인 SVG 로 보여 주고 고칠 수 있는 글자에 `data-editable` 을 달아 마우스를 올리면 주황색·글자 커서, 클릭하면 입력칸). 순수 계산 `conceptDiagram/inlineText.js` — `normText`({}·공백·대소문자 무시), `pickByText`(같은 글자가 여럿이면 화면에서 몇 번째인지), `responsiveSvg`, `sketchTextTargets`(손스케치에서 고칠 수 있는 모든 자리: 제목·부제·도형 이름·설명·화살표 라벨·메모·문구 블록·핵심 메시지·범례), `sketchApplyText`.
- 연결: 손스케치 편집기(SketchEditor)는 캔버스 더블클릭(+메모를 골라 Enter/F2)으로 글자 고치기(메모는 data-eid, 나머지는 글자 내용으로 자리를 찾음, 한 글자씩 되돌리기 칸이 생기지 않게 같은 항목은 묶음). 그 밖의 결과는 클릭 편집 → `setByPath` 로 스펙을 고쳐 왼쪽 목록과 같은 값을 공유. 페이지 모드의 편집 화면은 모든 종류의 결과에서 같은 방식(전환 버튼도 모든 종류), 새로 만들면 어떤 종류든 편집 화면으로.
- 되돌리기: 손스케치가 아닌 결과의 글자 편집은 `textHist`(같은 결과 ver 안에서 50단계) Ctrl+Z / Ctrl+Y, 입력칸 안의 Ctrl+Z 는 입력칸 동작.
- 시험: check_diagrams 176개(새 7개), 실제 앱 화면 부품에서 배치 개념도 예시(고칠 수 있는 글자 11개 표시, 클릭→입력칸→Enter 반영·왼쪽 목록 동시 반영·Esc 취소), 손스케치 결과(범례 글자·제목 더블클릭 편집, Esc 취소, 메모 선택 후 Enter), 글자 두 번 고치기→Ctrl+Z 두 번→Ctrl+Y 두 번, 입력칸 Ctrl+Z 격리, 페이지 모드 편집 화면에서 인라인 보기 확인.
- 시험 중 실수: 패치 명령 앞에 불필요한 `cat` 이 stdin 을 기다려 명령이 멈춰 패치가 적용되지 않은 채 시험해 첫 되돌리기 시험이 실패 → 패치를 다시 적용하고 재시험.
- 한계: 페이지 제목·칸 제목은 아직 그림 위 클릭이 아님(📐 상자 입력칸), 여러 줄 글자(줄바꿈)를 가진 일반 결과의 글자는 줄마다 따로 그려져 매칭이 안 될 수 있음(그 경우 안내 문구), AI 이미지 편집 결과의 원본 도면 속 글자는 이미지의 일부라 불가.

## 10. AI 이미지 편집 결과를 '편집 가능한 층'으로 (사용자 지적: "원래 다이어그램은 색상·위치·곡선·선 종류를 다 고칠 수 있었는데, 지금은 글자만 고쳐진다")
- **원인**: AI 이미지 편집 결과는 래스터 한 장(화살표·구역 색이 그림에 구워져 있음) + 글자 메모뿐이라 글자밖에 고칠 수 없었다. 사용자가 "AI 이미지 편집 결과"를 고쳐 달라고 선택.
- **서버(backend/services/diagram_vector.py 신규, diagram_edit.py 연결)**: 결과를 세 층으로 나눈다. ① 화살표 → 벡터 선(굵은 채색 선 마스크 → 뼈대 → 가장 긴 경로 + 곁가지 → 점 목록·굵기·색·화살촉·실선/파선/점선/일점쇄선, 꺾임이 뚜렷하면 꺾은선·아니면 곡선, 토막 난 같은 색 조각은 방향이 맞으면 합침, 굵은 화살촉의 곁가지·짧은 얼룩은 버림) ② 선 도면의 구역 색 → 색별 농도 마스크 + 기준 색(T ≈ 1 − Σ a·(1 − c), 곱하기), 사진·3D 의 구역 색 → '원래 없던 그 색이 새로 생긴 자리' 마스크(화면에서 color 혼합) ③ 바탕 = 선 도면은 화살표·구역 색을 뺀 원본(선·글자 그대로), 사진·3D 는 화살표 자리를 둘레 색으로 메운 결과. 같은 색 띠 화살표는 한 색으로 맞추고 범례 색도 그에 맞춘다. 작업 결과에 `layers`(base·arrows·zones·mode)가 추가됨. 못 나누면(`layers: null`) 예전처럼 합성 그림 한 장 + 글자 범례.
- **`composite()` 리팩터링**: 곱하기 판·화살표 마스크 계산을 `tint_parts()`로 분리(결과는 동일, 회귀 점검에 비교 추가).
- **화면(sketch.js)**: `makeEditSpec({layers})` → 화살표는 `winds`(shape 'read', 읽은 그대로의 점·곡선·선 종류·색·화살촉, 굵기는 화면 좌표로 환산), 구역 색은 `zones`(마스크+색+농도+숨김+blend). 렌더는 바탕 위에 `mask`+`mix-blend-mode`(multiply/color)로 칠한다(SVG→PNG 래스터로도 합성 그림과 평균 오차 1.6/255 이내 확인). 이미지 편집 화살표는 채운 삼각 화살촉(markerSize 4).
- **편집기(SketchEditor.jsx)**: ① "구역 색 (칠한 층)" 상자 — 층마다 색(연한 색 견본 + 색 선택기)·이름·농도·표시/숨김, 색·이름을 바꾸면 연결된 범례 글자(memo.zone)가 따라 바뀜 ② 선택한 화살표의 주황 점(pt:i)을 끌어 굽음·꺾임 수정, "＋ 점 추가 / － 점 빼기", "부드러운 곡선/꺾은선" 토글 + 기존 화살촉·선 표현(실선·파선·점선·일점쇄선·이중선…)·굵기·색·끝점 X/Y·방향 뒤집기·정렬 그대로.
- **페이지(page.js)**: 여러 칸에 같은 그림을 넣으면 마커·마스크 id 가 겹쳐 서로 덮어쓰던 것을 `scopeIds()`로 칸마다 접두어(`c0_`…)를 붙여 해결(한 칸 페이지는 그대로).
- **시험**: check_diagrams 176 → 197개 통과(층 변환·좌표·굵기·범례 연결·점 편집 bend 역산·손잡이·왕복·id 접두어), check_fast 에 합성 이미지로 층 나누기 시험 추가(화살표 위치·굵기·색·파선+화살촉·마스크 범위·바탕 복원·재합성 오차·사진 모드) 모두 통과. 저장해 둔 실제 결과(아파트 평면·항공 배치·렌더 일조·SketchUp 기능별 매스)로 시험: 아파트 평면 화살표 17개·구역 4층, 배치 항공 8개, 일조 렌더 3개, 기능별 매스 구역 3층(주황→파랑·보라→빨강 재색칠 확인).
- **알려진 한계**: 자동으로 뽑는 것이라 완벽하지 않다(겹친 화살표는 갈라 읽고 어긋날 수 있음, 점선 종류는 가장 가까운 것으로 분류, 화살촉이 흐리면 빠짐). 못 뽑은 화살표 조각은 바탕에서 사라질 수 있다(굵은 색 면은 바탕에 남김). 사진·3D 의 구역 마스크는 색 띠 기준이라 같은 색이 원래 있던 곳(잔디 등)은 제외되지만 경계가 거칠 수 있다. 원본 도면 속 글자·선(방 이름 등)은 여전히 이미지의 일부.
