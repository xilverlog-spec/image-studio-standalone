## 2. 출력 크기 · 칸 나누기 · 글자 위계 (사용자 요청: 다이어그램 사이즈를 정하고, 글자 위계(pt)·글씨체를 추천받고, 한 페이지를 칸으로 나눠 칸 하나를 골라 그 크기에 맞게 만들기)
- 설계: 렌더러마다 캔버스·글자 크기가 코드에 고정돼 있어(모두 같은 SVG 구조와 같은 글꼴 상수) 렌더러를 고치지 않고 **페이지 층**(`src/conceptDiagram/page.js`)이 결과 SVG 를 받아 정해진 mm 페이지 안에 맞춘다. 렌더러 안의 글자 크기는 못 바꾸므로 '맞춘 뒤의 실제 pt'를 계산해 추천값과 견주어 보여 주고 경고한다(제목·소제목·칸 제목은 페이지 층이 직접 pt 로 그림).
- 구현: ① 용지 프리셋(A4·A3·A2·A1 가로/세로, PPT 16:9·4:3, 직접 입력 mm) ② 칸 나누기 13가지 + `g가로x세로` 격자(최대 6×6), 칸 간격(mm), 칸 번호 c1… ③ `recommendType`: 인쇄는 A3 짧은 변 기준 32/18/11/8pt 를 짧은 변에 비례(A4 23/13/8/6, A1 64/36/22/16), 화면은 PPT 16:9 기준 36/22/14/11pt 를 면적 제곱근에 비례, 최소 읽기 크기(인쇄 7pt·화면 11pt) ④ `composePage`: 제목·소제목(페이지) + 칸마다 칸 제목(소제목 pt) + 그림을 칸 안에 맞춤(clip), 글꼴 교체(맑은 고딕·Noto Sans KR·Pretendard·나눔고딕·돋움·바탕), 용지 mm 크기의 SVG(`width="420mm"`)와 96dpi 기준 픽셀 크기, 경고(너무 작음·목표보다 작거나 큼·위계 어긋남·긴 제목 축소·제목이 자리를 많이 차지함), 미리보기(칸 테두리·빈 칸·고른 칸 강조) ⑤ `typeTiers`: 그림 안 글자 크기를 소제목급/본문(가장 많이 쓰인 크기)/가장 작은 글자로 나눔 ⑥ 브라우저에서 `domMeasure`(getBBox)로 그림의 실제 내용 영역을 재서 렌더러가 비워 둔 여백을 잘라 칸을 알뜰히 씀(없으면 sketch 의 제목 자리 띠만 `sketchContentTop` 으로 자름) ⑦ 패널이 여러 개인 렌더러(layout2d·siteConcept·massing)는 `spec.cols` 를 받도록 하고 `bestCols` 가 칸 가로세로 비율에 가장 가까운 열 수를 고름.
- 화면: `src/PageBox.jsx`(📐 상자: 켜기, 용지·가로세로·용도, 칸 나누기·간격·직접 격자, 칸 버튼(칸 mm 크기·채움 표시)·칸 비우기·예시 그림 넣어 보기, 제목/소제목/본문/작은 글자 pt(추천값은 placeholder, 직접 입력 우선, 지금 결과의 실제 pt 표시), 글씨체와 용도별 추천, 그림 맞춤(꽉 채우기/본문 목표 pt), PNG 해상도, 페이지 제목·소제목, 경고). 칸마다 결과를 따로 두고(`cells`), 고른 칸의 결과가 지금 편집·만들기 대상(`result`)이며 칸을 바꾸면 그 칸 결과를 불러옴. 오른쪽에 페이지 미리보기(칸을 눌러 고름) + 고른 칸이 손스케치면 편집기. SVG 저장은 mm 크기 페이지, PNG 저장은 선택한 dpi(캔버스 한계 약 1.2만 px 를 넘으면 줄임). 설정은 localStorage 에 기억(제목 칸은 제외).
- 시험: check_diagrams 124개(새로 46개: 추천 pt·위계·가로세로 같은 짧은 변, 글꼴 상수 일치, 실제 mm 크기 저장, 제목 32pt·소제목 18pt·칸 제목 18pt 정확도, 다른 비율 용지에도 그림이 용지 안, 작은 용지 경고, 본문 목표 pt 맞춤, 긴 제목 축소, 칸 나누기 13종이 영역 안에서 겹치지 않음, 칸 간격 10mm, 칸 비율별 패널 열 수, 4칸 중 2칸 채움·미리보기 표시), 실제 앱 화면 부품에서 2칸 + 예시 그림 두 개 + 칸 선택 + 페이지 제목 32pt 확인, A3 L자형 3칸 샘플을 Edge 로 찍어 모양 확인.
- 한계: 칸을 끌어 크기를 바꾸거나 합치는 편집은 없음(프리셋·격자만), 칸을 고른 뒤 만드는 AI 단계는 칸 크기를 모르고 만든 뒤 맞추는 방식(패널 배열만 칸 비율에 맞춰짐), 다이어그램 속 글자는 pt 를 직접 지정하지 못하고 실제 pt 를 계산해 경고만 함, 글꼴은 저장한 SVG 를 여는 PC 에 설치돼 있어야 그대로 보임, 브라우저 창이 너무 작아서 화면 모양은 눈으로 못 보고 DOM·계산·Edge 렌더로 확인.

## 3. 칸 직접 끌어서 크기 조절 + 바깥 여백·테두리선 (사용자 요청)
- 요청: 칸을 나눈 뒤 그림에서 직접 사각형을 움직여 크기를 조절, 겉 가장자리 테두리 간격도 설정.
- 배치 데이터: 칸마다 `{ id, r:[왼쪽,위,오른쪽,아래] }`(페이지 안쪽 영역 대비 0~1). 프리셋을 끌면 모양을 복사해 `layoutId:'custom'` + `pg.custom` 이 되고(`basePreset` 에 처음 프리셋을 기억해 '배치 되돌리기'), 칸 번호(id)는 끌기·나누기·삭제에도 유지돼 칸의 그림이 따라간다(`getCells`·`normalizeCustom`·`presetToCustom`, 최대 12칸).
- 끌기 계산(순수 함수, page.js): `dragEdge`(가장자리 하나. group=기본이면 같은 선에 맞닿은 칸의 가장자리도 함께 → 경계선 끌기, Alt 면 그 칸만; 최소 25mm, 가운데·다른 칸·바깥 가장자리에 3mm 안쪽이면 붙음), `dragMove`(칸 옮기기, 바깥 못 나감, 붙기), `setCellMm`(mm 입력), `splitCell`(좌우/위아래 반으로, 새 id), `removeCell`, `overlappingCells`.
- 화면: 미리보기의 칸 위에 투명 덮개(칸 고르기·몸통 끌어 옮기기)와 고른 칸의 8개 점(크기 조절). 끄는 동안은 가벼운 윤곽선과 크기(mm) 표시만 하고 손을 떼면 한 번만 다시 그림(끌 때마다 그림·이미지를 다시 그리면 느려서). window 의 pointermove/up 으로 처리해 칸 밖으로 나가도 이어짐. PageBox: 고른 칸 X·Y·가로·세로(mm), 나누기·삭제·배치 되돌리기.
- 바깥 여백: `composePage` 의 `margin`(null=자동 인쇄 8mm·화면 6mm 이상, 짧은 변의 4% / 숫자 한 값 / {t,b,l,r}), 빈 칸은 자동, 0 허용, 한 변은 용지의 30%까지, 위·아래/왼쪽·오른쪽 여백이 커서 그림 자리가 반 미만이면 경고. 제목·소제목은 왼쪽 여백에서 시작하고 폭도 좌우 여백을 뺀다. 테두리선 `frame`(굵기 pt→mm, 간격 mm 비우면 가장 작은 여백의 절반, 색). 화면: '자동' 옆에 자동값(mm) 표시, 직접 입력으로 바꾸면 현재 값으로 시작, '네 변 같게'.
- 시험: check_diagrams 152개(새로 28개: 끌기 6종(경계선 4칸 동시·Alt 한 칸·최소 크기·가운데에 붙기·L자 배치·세로 방향)·겹침 없음·옮기기·mm 입력·나누기·삭제·12칸 한도·custom 정리·mm 크기(raw)·custom 배치 조립, 여백 자동/한 값/변마다/0·빈 칸·30% 제한·제목 위치·테두리선(기본 간격·지정·끄면 없음)·경고), 실제 앱 화면 부품에서 포인터 이벤트로 2×2 의 가운데 경계선을 100px 끌기(195→234/156mm 네 칸 동시, '직접 조정한 배치'로 전환, 끄는 동안 크기 표시), Alt 끌기(한 칸만), mm 입력(150), 나누기(5칸), 삭제, 배치 되돌리기(2×2 복귀), 여백 자동→직접→네 변 같게→따로, 테두리선 기본 간격 7.5mm 확인.
- 한계: 칸을 삭제해도 비운 자리는 이웃에 합쳐지지 않음, 칸 겹침을 막지는 않고 알리기만(Alt 끌기·옮기기), 끄는 동안 그림은 갱신되지 않음(윤곽선만), 터치 화면은 시험하지 못함, 모니터가 작은 창에서 점이 작게 느껴질 수 있음(11px).
