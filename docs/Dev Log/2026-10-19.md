## 2. 출력 크기 · 칸 나누기 · 글자 위계 (사용자 요청: 다이어그램 사이즈를 정하고, 글자 위계(pt)·글씨체를 추천받고, 한 페이지를 칸으로 나눠 칸 하나를 골라 그 크기에 맞게 만들기)

## 3. 칸 직접 끌어서 크기 조절 + 바깥 여백·테두리선 (사용자 요청)
- 요청: 칸을 나눈 뒤 그림에서 직접 사각형을 움직여 크기를 조절, 겉 가장자리 테두리 간격도 설정.
- 배치 데이터: 칸마다 `{ id, r:[왼쪽,위,오른쪽,아래] }`(페이지 안쪽 영역 대비 0~1). 프리셋을 끌면 모양을 복사해 `layoutId:'custom'` + `pg.custom` 이 되고(`basePreset` 에 처음 프리셋을 기억해 '배치 되돌리기'), 칸 번호(id)는 끌기·나누기·삭제에도 유지돼 칸의 그림이 따라간다(`getCells`·`normalizeCustom`·`presetToCustom`, 최대 12칸).
- 끌기 계산(순수 함수, page.js): `dragEdge`(가장자리 하나. group=기본이면 같은 선에 맞닿은 칸의 가장자리도 함께 → 경계선 끌기, Alt 면 그 칸만; 최소 25mm, 가운데·다른 칸·바깥 가장자리에 3mm 안쪽이면 붙음), `dragMove`(칸 옮기기, 바깥 못 나감, 붙기), `setCellMm`(mm 입력), `splitCell`(좌우/위아래 반으로, 새 id), `removeCell`, `overlappingCells`.
- 화면: 미리보기의 칸 위에 투명 덮개(칸 고르기·몸통 끌어 옮기기)와 고른 칸의 8개 점(크기 조절). 끄는 동안은 가벼운 윤곽선과 크기(mm) 표시만 하고 손을 떼면 한 번만 다시 그림(끌 때마다 그림·이미지를 다시 그리면 느려서). window 의 pointermove/up 으로 처리해 칸 밖으로 나가도 이어짐. PageBox: 고른 칸 X·Y·가로·세로(mm), 나누기·삭제·배치 되돌리기.
- 바깥 여백: `composePage` 의 `margin`(null=자동 인쇄 8mm·화면 6mm 이상, 짧은 변의 4% / 숫자 한 값 / {t,b,l,r}), 빈 칸은 자동, 0 허용, 한 변은 용지의 30%까지, 위·아래/왼쪽·오른쪽 여백이 커서 그림 자리가 반 미만이면 경고. 제목·소제목은 왼쪽 여백에서 시작하고 폭도 좌우 여백을 뺀다. 테두리선 `frame`(굵기 pt→mm, 간격 mm 비우면 가장 작은 여백의 절반, 색). 화면: '자동' 옆에 자동값(mm) 표시, 직접 입력으로 바꾸면 현재 값으로 시작, '네 변 같게'.
- 시험: check_diagrams 152개(새로 28개: 끌기 6종(경계선 4칸 동시·Alt 한 칸·최소 크기·가운데에 붙기·L자 배치·세로 방향)·겹침 없음·옮기기·mm 입력·나누기·삭제·12칸 한도·custom 정리·mm 크기(raw)·custom 배치 조립, 여백 자동/한 값/변마다/0·빈 칸·30% 제한·제목 위치·테두리선(기본 간격·지정·끄면 없음)·경고), 실제 앱 화면 부품에서 포인터 이벤트로 2×2 의 가운데 경계선을 100px 끌기(195→234/156mm 네 칸 동시, '직접 조정한 배치'로 전환, 끄는 동안 크기 표시), Alt 끌기(한 칸만), mm 입력(150), 나누기(5칸), 삭제, 배치 되돌리기(2×2 복귀), 여백 자동→직접→네 변 같게→따로, 테두리선 기본 간격 7.5mm 확인.
- 한계: 칸을 삭제해도 비운 자리는 이웃에 합쳐지지 않음, 칸 겹침을 막지는 않고 알리기만(Alt 끌기·옮기기), 끄는 동안 그림은 갱신되지 않음(윤곽선만), 터치 화면은 시험하지 못함, 모니터가 작은 창에서 점이 작게 느껴질 수 있음(11px).

## 4. 단축키 + 글자 위계 안전장치 (사용자 요청: 기본적인 단축키 / "이거 정확히 어떤 위계인지 설명해줘" — 제목이 작고 소제목이 큰 화면)
- 단축키(ConceptDiagram 창 전체 keydown, 이 탭이 안 보이면 무시, 입력칸에 글자 입력 중에는 Ctrl+Enter·Ctrl+S 만): Ctrl+Z/Y(Ctrl+Shift+Z) 페이지 되돌리기·다시 하기, Delete 칸 비우기(Shift 칸 삭제), 방향키 이동 1mm(Shift 10)·Alt 크기, Tab/Shift+Tab 칸 이동, Esc 끌기 취소, Ctrl+C/V/D 칸 내용 복사·붙여넣기·빈 칸에 복제, Ctrl+S/Ctrl+Shift+S 저장, Ctrl+Enter 만들기.
- 페이지 되돌리기 기록: 칸 배치(layoutId·custom·basePreset)·칸 안 결과(cells)·고른 칸을 스냅샷으로 60단계까지, 같은 종류의 연속 동작(방향키·mm 입력)은 0.8초 안이면 한 번으로 묶음. 새 그림이 칸에 들어갈 때만 기록(type 또는 ver 가 바뀔 때; 모든 결과에 ver 를 달았음), 같은 그림을 고치는 것은 편집기가 기록. 칸 배치 선택(프리셋·격자)도 기록.
- 손스케치 편집기와의 충돌 방지: 편집기도 창 전체에서 Ctrl+Z/C/V/D·Delete·방향키를 받으므로, 마지막에 만진 곳(`ctxRef`: 페이지 미리보기·설정 상자='page', 편집기='sketch')을 기록하고 편집기는 `shortcutsEnabled()` 가 false 일 때(page 를 만진 직후) 키를 무시.
- 글자 위계: 표준 용지 추천값은 항상 제목>소제목>본문>작은 글자(A3 32/18/11/8, A4 23/13/8/6, A1 64/36/22/16, PPT 36/22/14/11). 빈틈 두 가지를 고침: ① 직접 넣은 pt 가 거꾸로(제목 6·소제목 40)여도 경고 없이 따르던 것 → 빨간 경고 추가(제목>소제목, 소제목>본문, 본문>작은 글자 점검) ② 아주 작은 직접 입력 용지(예: 42×29.7mm)에서 본문 바닥값(7pt) 때문에 제목 3pt < 본문 7pt 로 뒤집히던 것 → 바닥값으로 본문이 올라가면 소제목(본문×1.3 이상)·제목(소제목×1.4 이상)도 올림.
- 시험: check_diagrams 158개(위계 6개 추가), 실제 앱 화면 부품에서 키 이벤트로 끌기→Ctrl+Z(2×1 복귀)→Ctrl+Y(custom), Delete→Ctrl+Z, 방향키(x +1·+10, Alt 로 가로 +1), Tab/Shift+Tab 확인.

## 5. 그림 속 글자를 본문 목표 pt 에 맞춰 넣기 (사용자 지적: 칸에 넣으면 그림 속 글자가 23pt 로 소제목(18pt)보다 커져 위계가 깨짐)
- 원인: 그림 속 글자 크기는 렌더러가 정한 px 이고 칸에 맞추는 배율 s 가 그대로 곱해져, 큰 칸에 작게 그려진 그림은 글자가 커짐(경고만 하고 안 고침).
- 구현: `scaleTexts(svg, k)` — 렌더러 SVG 의 `<text font-size y>` 를 직접 고쳐 글자 크기만 k 배(그림·도형은 그대로), 글자 가운데 위치를 지키도록 기준선 `y' = y − 0.35·fs·(1−k)`, 글자 둘레 흰 테두리(stroke-width)도 같은 비율, 회전·dy·baseline·textLength 글자는 제외. `composePage` 에 `fit` 모드: `fill`(칸 꽉 채움, 글자는 그림 배율 따름, 기존·시험용 기본) / `text`(본문 글자를 목표 pt 에 맞추기, 그림을 줄임) / **`both`(칸 꽉 채우고 글자만 목표 pt, 앱 기본)**. `both` 의 글자 배율 k = 목표 pt·0.3528 ÷ (그림 배율 s × 원래 본문 크기), 1.3배(키울 때 칸 밖으로 넘침)~0.3배로 제한. 그림 속 글자끼리 비율(소제목급·본문·작은 글자)은 유지. 보고에 `textScale`.
- 화면: 📐 상자 '그림·글자 맞춤' 세 가지(권장 both 기본) + 설명, `pg.fit`(옛 `pg.fill` 은 쓰지 않음).
- 시험: check_diagrams 169개(새 11개: scaleTexts 기준선·테두리·제외 글자·배율 1, 큰 칸에서 fill 은 본문이 목표보다 큼 / both 는 같은 배율에서 본문이 목표 pt·위계 경고 없음·글자 배율 공식·0.3~1.3 제한), 실제 앱 화면에서 기본 both·'지금 결과 11pt' 확인, 층별 조닝 예시를 Edge 로 fill(층 이름 15.2pt) 대 both(11pt) 비교.
- 한계: 사진·AI 이미지 편집 결과에 박힌 글자는 그림 일부라 못 바꿈. 글자를 키워야 하는 경우(k>1)는 칸 안에서 겹칠 수 있어 1.3배까지만. 글자를 줄이면 라벨이 박스 안에서 상대적으로 작아 보일 수 있음.

## 6. "다이어그램 수정하는 페이지가 없어졌다" → 페이지 모드에서 편집기가 화면 아래로 밀려 있었음
- 원인(시험 페이지로 재현): 페이지 모드에서는 오른쪽 위에 페이지 미리보기(약 768px)가 먼저 놓이고 손스케치 편집기가 그 아래(864px, 보이는 영역 893px 의 맨 끝)에 놓여 스크롤을 내려야만 보였다. 게다가 페이지 모드 켬 여부를 localStorage 에 기억해 다음에 열어도 켜진 채 시작 → 켠 것을 잊으면 편집기가 없어진 것처럼 보임. 페이지 모드를 끈 일반 상태에서는 편집기가 맨 위(81px)에 정상.
- 수정: ① 페이지 모드는 기억하지 않고 항상 꺼진 채로 시작(설정만 기억) ② 오른쪽 위 전환 버튼 [📄 페이지 배치·칸 크기 조절] / [✏️ 선택한 칸 편집](손스케치 결과일 때) + [페이지 모드 끄기], 한 번에 한 화면만 보임 ③ 새로 만든 손스케치류 결과(생성·AI 이미지 편집)는 자동으로 편집 화면, 페이지 모드를 켤 때는 페이지 배치 화면 ④ 칸 더블클릭 = 그 칸 편집 ⑤ 화면을 바꾸면 단축키 받는 쪽도 같이 바뀜(편집=손스케치 편집기, 페이지=페이지 단축키).
- 시험(실제 앱 화면 부품 + 가짜 서버): 끈 상태 편집기 맨 위, 켜면 전환 버튼 3개·페이지 화면, 편집 전환(편집기 153px·칸 크기 안내 문구), 되돌아가기, 칸 더블클릭, 끄기(편집기 81px 복귀), 페이지 화면에서 새로 만들면 편집 화면으로 자동 전환, 편집 화면의 Ctrl+Z 는 편집기가 받고 페이지 안내 알림이 안 뜸.
- 확인 못 한 것: 실제 앱(프로젝트 비밀번호 필요)에는 들어가지 못해 같은 화면 부품으로 시험함.

## 10. AI 이미지 편집 결과를 '편집 가능한 층'으로 (사용자 지적: "원래 다이어그램은 색상·위치·곡선·선 종류를 다 고칠 수 있었는데, 지금은 글자만 고쳐진다")
- **원인**: AI 이미지 편집 결과는 래스터 한 장(화살표·구역 색이 그림에 구워져 있음) + 글자 메모뿐이라 글자밖에 고칠 수 없었다. 사용자가 "AI 이미지 편집 결과"를 고쳐 달라고 선택.
- **서버(backend/services/diagram_vector.py 신규, diagram_edit.py 연결)**: 결과를 세 층으로 나눈다. ① 화살표 → 벡터 선(굵은 채색 선 마스크 → 뼈대 → 가장 긴 경로 + 곁가지 → 점 목록·굵기·색·화살촉·실선/파선/점선/일점쇄선, 꺾임이 뚜렷하면 꺾은선·아니면 곡선, 토막 난 같은 색 조각은 방향이 맞으면 합침, 굵은 화살촉의 곁가지·짧은 얼룩은 버림) ② 선 도면의 구역 색 → 색별 농도 마스크 + 기준 색(T ≈ 1 − Σ a·(1 − c), 곱하기), 사진·3D 의 구역 색 → '원래 없던 그 색이 새로 생긴 자리' 마스크(화면에서 color 혼합) ③ 바탕 = 선 도면은 화살표·구역 색을 뺀 원본(선·글자 그대로), 사진·3D 는 화살표 자리를 둘레 색으로 메운 결과. 같은 색 띠 화살표는 한 색으로 맞추고 범례 색도 그에 맞춘다. 작업 결과에 `layers`(base·arrows·zones·mode)가 추가됨. 못 나누면(`layers: null`) 예전처럼 합성 그림 한 장 + 글자 범례.
- **`composite()` 리팩터링**: 곱하기 판·화살표 마스크 계산을 `tint_parts()`로 분리(결과는 동일, 회귀 점검에 비교 추가).
- **화면(sketch.js)**: `makeEditSpec({layers})` → 화살표는 `winds`(shape 'read', 읽은 그대로의 점·곡선·선 종류·색·화살촉, 굵기는 화면 좌표로 환산), 구역 색은 `zones`(마스크+색+농도+숨김+blend). 렌더는 바탕 위에 `mask`+`mix-blend-mode`(multiply/color)로 칠한다(SVG→PNG 래스터로도 합성 그림과 평균 오차 1.6/255 이내 확인). 이미지 편집 화살표는 채운 삼각 화살촉(markerSize 4).
- **편집기(SketchEditor.jsx)**: ① "구역 색 (칠한 층)" 상자 — 층마다 색(연한 색 견본 + 색 선택기)·이름·농도·표시/숨김, 색·이름을 바꾸면 연결된 범례 글자(memo.zone)가 따라 바뀜 ② 선택한 화살표의 주황 점(pt:i)을 끌어 굽음·꺾임 수정, "＋ 점 추가 / － 점 빼기", "부드러운 곡선/꺾은선" 토글 + 기존 화살촉·선 표현(실선·파선·점선·일점쇄선·이중선…)·굵기·색·끝점 X/Y·방향 뒤집기·정렬 그대로.
- **페이지(page.js)**: 여러 칸에 같은 그림을 넣으면 마커·마스크 id 가 겹쳐 서로 덮어쓰던 것을 `scopeIds()`로 칸마다 접두어(`c0_`…)를 붙여 해결(한 칸 페이지는 그대로).
- **시험**: check_diagrams 176 → 197개 통과(층 변환·좌표·굵기·범례 연결·점 편집 bend 역산·손잡이·왕복·id 접두어), check_fast 에 합성 이미지로 층 나누기 시험 추가(화살표 위치·굵기·색·파선+화살촉·마스크 범위·바탕 복원·재합성 오차·사진 모드) 모두 통과. 저장해 둔 실제 결과(아파트 평면·항공 배치·렌더 일조·SketchUp 기능별 매스)로 시험: 아파트 평면 화살표 17개·구역 4층, 배치 항공 8개, 일조 렌더 3개, 기능별 매스 구역 3층(주황→파랑·보라→빨강 재색칠 확인).
- **알려진 한계**: 자동으로 뽑는 것이라 완벽하지 않다(겹친 화살표는 갈라 읽고 어긋날 수 있음, 점선 종류는 가장 가까운 것으로 분류, 화살촉이 흐리면 빠짐). 못 뽑은 화살표 조각은 바탕에서 사라질 수 있다(굵은 색 면은 바탕에 남김). 사진·3D 의 구역 마스크는 색 띠 기준이라 같은 색이 원래 있던 곳(잔디 등)은 제외되지만 경계가 거칠 수 있다. 원본 도면 속 글자·선(방 이름 등)은 여전히 이미지의 일부.

## 11. 모든 결과에서 색·위치·곡선·선 종류를 고치기 (사용자: "오늘 처음 테스트할 때까지만 해도 수정 기능이 있었잖아" → 확인 질문에 "기억이 정확하지 않다 — 모든 결과에서 되게 해 줘")
- **확인한 사실**: 오늘 첫 테스트(연구시설 평면 '동선', 평면 다이어그램 방식)의 화면은 그림 + 글자 수정만 있었고 도형 편집 패널은 없었다. 코드 이력(ConceptDiagram.jsx 10-16 17:20 이후 diff)에도 지워진 편집 기능은 없다. 전체 도형 편집기(SketchEditor)는 원래 손스케치류 결과에만 있었고, 구조형 결과(평면 다이어그램·배치 개념도·매스·버블도·층별 조닝도)는 `<img>`+글자 목록뿐이었다. draw.io 자유 편집(DrawioEditor.jsx)은 10-06 에 화면에서 뺀 상태(DiagramModule.jsx 주석). 사용자가 방향을 정해 줌: 모든 결과에서 되게.
- **방식**: 그림(SVG) 자체를 요소 단위로 고치는 범용 편집기. 결과 종류마다 변환기를 만들면 해칭·아이콘·부지 모양이 손실되고 종류가 늘 때마다 다시 만들어야 해서, 렌더러가 내는 SVG 를 그대로 고른다.
  - `src/conceptDiagram/svgedit.js`(순수 함수·DOM 불필요): `scanSvg`(defs·marker·pattern 밖의 도형·글자를 e#, 묶음을 g# 로 문서 순서대로 번호 + 구조 지문 sig), `applyEdits`(요소 번호별 수정을 문자열에 입힘: 이동=transform 앞에 translate, 속성 바꾸기/제거, 삭제=display none, line→path 변환; `ids` 옵션이면 편집용 data-eid 와 얇은 선 눌림용 투명 덧선), 수정 만들기(불변: editSet/Move/Delete/Restore/AsPath), 선 종류 프리셋, 경로 해석(M L H V C S Q T A Z·상대좌표→절대 M L C Q A Z)과 마디 편집(옮기기·제어점·직선↔곡선·점 추가(곡선은 모양 유지 분할)·빼기), 꼭짓점 목록.

## 13. 글자를 누르면 몇 pt 인지 알려주기 (사용자 요청)
- 그림 속 글자를 클릭하면 오른쪽에 주황색 상자 "🔤 ‘글자’ 약 N pt"와 어느 크기 기준인지가 나온다(구조형 결과: SvgEditor, 손스케치류: SketchEditor — 제목·도형 이름·범례 등 모든 글자, 메모는 크기 칸 옆에도 표시).
- 환산(`ptInfoOf`): 페이지 모드면 그 칸의 실제 배율(scale, mm/그림 단위)과 글자 맞춤 배율(textScale)을 곱해 pt = 글자크기 × scale × textScale / PT_MM, 아니면 저장 그림 크기 96dpi 기준(1px = 0.75pt)이라고 밝히고 페이지 크기를 정하면 그 용지 기준으로 보인다고 안내. 글자 자신의 font-size 에 바깥 묶음(g)의 transform 확대·축소를 곱한 실제 크기(`textUnitSize`)를 쓴다.
- 시험(실제 ConceptDiagram 부품): 페이지 모드 끈 상태 17px → 12.8pt, 15px → 11.3pt. 켠 상태(A4 가로, 글자 맞춤 ×0.72) 9.1pt·8pt 로, 페이지 SVG 의 같은 글자(font-size × 칸 배율 / PT_MM)를 직접 계산한 값 9.1pt·8pt 와 일치. 손스케치 편집기는 제목 26 → 5.2pt, 메모 15 → 3pt(시험 배율 0.2).

## 16. 구조형 결과 편집기를 손스케치 편집기 수준으로 (사용자: "그 순서대로" — 1단계 요소 추가 → 2단계 복사·여러 개 선택 → 3단계 정렬·안내선)
- **1단계 요소 추가**: `edits.shapes`(글자·사각형·원·화살표). 그림 맨 끝에 붙여 본래 요소 번호가 바뀌지 않고(새 도형은 그 뒤 번호 e{본래 요소 수+i}), 구조 지문(sig)은 새 도형을 빼고 계산해 영향이 없다. 새 도형도 일반 요소라 같은 편집기(색·이동·곡선·선 종류)가 그대로 먹는다. 화살표는 마커 `fill="context-stroke"`(선 색을 따라감, 브라우저가 지원하지 않으면 색을 직접 지정 — 실행 중 한 번 감지), 글자는 여러 줄 tspan·ENGINE_FONT. 지우면 뒤 도형의 번호·수정을 한 칸씩 당김(`editRemoveShape`). 새로 만든 요소는 그림이 다시 그려진 뒤에야 화면에 있으므로 그 한 번의 그림에서는 속성 상자를 그리지 않게 막음(그전에는 속성 상자가 null 을 읽어 편집기 전체가 죽었다).
- **2단계 복사·여러 개 선택**: `kind:'raw'` 도형 = 지금 보이는 요소 한 개를 그대로 복제(조상 묶음의 변환을 matrix 로 굳히고, 물려받은 색·굵기·글꼴을 속성으로 굳히고, 참조하는 마커·무늬는 새 이름으로 함께 복사). Ctrl+C/V/D·버튼, 붙인 것은 비껴 놓이고 바로 선택, 이미지(adds)도 복사. 여러 개 선택(Shift·Ctrl+클릭, 배경을 끌어 상자 선택, Ctrl+A), 모두 함께 끌기·방향키·Delete·색/굵기/선 종류/투명도 일괄. 복사한 글자는 더블클릭으로 고침(`rawSetText`).

## 17. AI 이미지 편집: 화살표·구역 자동 추출 정확도 + '이 영역만 다시 그리기' (사용자: "3번으로 진행해줘")
- **추출 정확도(backend/services/diagram_vector.py)**: ① 얇은 점선(1~2화소 점)·파선 조각이 서로 떨어져 끊긴 화살표로 읽히던 것 → 겹침 선(overlay) 결과에서만 `disk(max(3, round(S*0.007)))` 팽창으로 묶어 한 화살표로 이음. ② 선에서 떨어진 **화살촉만 있는 덩어리**를 버리던 것 → `_head_blobs`(열림 연산으로 얻은 덩어리의 밑변·끝점을 SVD 로 계산)로 살려 화살촉 있는 화살표로 남기고 점선 조각과 이어 붙임. 사진 속 파선 조각에 헛 화살촉이 붙는 것은 "주변 선 굵기의 1.45배 이상"인 덩어리만 인정하고 이미 있는 선 위의 덩어리는 건너뛰어 막음. 두꺼운 화살표가 머리 한 조각으로 무너지던 회귀(조감도·투시도)는 머리만 있는 덩어리를 `longest <= 7*ww` 일 때만 인정해 해결. ③ 색 띠로 칠한 구역의 연한 면이 선으로 오인되던 것 → `sensitive_core`가 구역 색 띠를 제외(아파트 시험에서 거짓 화살표 사라짐). ④ 최소 조각 크기를 `max(14, int(2e-5*S*S))` 로 그림 크기에 비례.

- **고친 버그**: ConceptDiagram 에서 `selCell` 을 선언 전에 쓰는 effect 를 넣어 화면이 하얗게 되는 오류(ReferenceError, 빌드는 통과 — 실행해 봐야 알 수 있음) → effect 를 `useState` 선언 뒤로 이동. 실제 부품을 띄운 시험 도구로 발견.

## 18. 내 이미지 보완(붙여넣기·여러 장·바꾸기·자르기·화질) + 페이지·출력 보완(나란히 보기·제목 바로 고치기·글자 위계 경고) (사용자: "일단 5번까지 진행해줘")
- **붙여넣기(Ctrl+V)**: `ConceptDiagram` 이 `document` 의 paste 를 받아 클립보드의 이미지를 지금 칸(페이지 모드면 고른 칸)에 넣는다. 입력칸·글자칸에서는 무시하고, 다이어그램 탭이 숨겨져 있으면(`getClientRects` 비어 있음) 건드리지 않는다. **편집기 안 복사·붙여넣기와 단축키를 나눠 쓰기**: 두 편집기의 Ctrl+V 는 예전엔 keydown 에서 바로 붙이고 막아 버렸다 → `clip.js` 의 `schedulePaste`(0ms 대기)로 바꿔 곧 이어지는 paste 이벤트에 이미지가 있으면 이미지가 이기고(`cancelPendingPaste`), 없으면 편집기에서 복사한 요소를 붙인다. 편집기에서 Ctrl+C/X 를 하면 `markInternalCopy`(숨은 textarea + `execCommand('copy')`, http 사내망에서도 동작)로 시스템 클립보드를 글자 표식으로 덮어써서 **예전에 복사해 둔 캡처가 다음 Ctrl+V 에서 되살아나지 않게** 했다. 진짜 키 입력(trusted)에서 copy 이벤트가 TEXTAREA 로 발생하는 것까지 확인(합성 이벤트는 사용자 동작으로 치지 않아 execCommand 가 안 돎).
- **여러 장 한 번에**(`insertMyImages`, 최대 12장): 읽는 동안 화면이 바뀔 수 있어 읽은 뒤 `latest` ref 의 최신 상태로 계산하고 한 번에 반영(페이지 모드는 `pushHistory` 1회 + `setCells` 일괄). 빈 칸에 놓으면 **시작 칸부터 칸 순서대로 이어서(끝에서 처음으로) 빈 칸을 채우고**, 그림이 있는 칸·빈 화면의 둘째 장부터·빈 칸이 모자란 나머지는 **그 그림 안에 얹되 `stagger`(3씩, 8장마다 되풀이)로 비껴 놓음**. 파일 선택 창 `multiple`, 끌어다 놓기·붙여넣기 모두 같은 함수.
- **화질 3단계**(`IMG_QUALITY`): 가볍게 1000px/120만자, 보통 1600px/280만자(기존), 선명하게 2600px/550만자(손스케치 이미지 한도 600만자 안). 투명 배경이 있을 수 있는 형식은 PNG 유지. 선택은 localStorage, 넣은 뒤 안내에 px·KB 표시(`readImageFile` → `{url,w,h,kb}`).
- **이미지 바꾸기·자르기**: 데이터는 이미지 블록(손스케치 `sketchReplaceImage/sketchCropImage`)과 구조형 `edits.adds`(`editReplaceImage/editCropImage`) 양쪽에 같은 모양 — `orig`(원본 data URL) + `crop`([l,t,r,b] 원본에 대한 0~1) + 자른 그림이 `href`. **픽셀로 구워 넣는 방식**이라 SVG·PNG·페이지 출력·복사·일러스트레이터 열기에서 다른 처리가 필요 없다(중첩 svg·clipPath 방식은 선택 상자·내보내기와 어긋날 위험이 있어 버림). `cropRect` 가 보이는 부분이 제자리에 남게 상자를 줄이고(`oldCrop`→`newCrop`), 다시 열면 원본에서 범위를 고친다. 구운 그림만 그림(SVG)에 들어가고 orig/crop 은 새지 않음(시험). `ImageCropDialog`(끌어서 고르는 주황 상자 + 점 8개, Enter/Esc, 전체로) 가 열려 있는 동안 편집 단축키(Delete 등)는 받지 않게 막음. **고친 버그**: 바꾸기에 `{href}` 대신 읽은 결과 객체(`url`)를 그대로 넘겨 이미지 블록이 사각형으로 바뀌었다(화면 시험에서 발견) → 호출을 고치고, 새 그림 주소가 없으면 아무것도 바꾸지 않는 방어를 4개 함수에 추가(회귀 시험).
- **화면 배치(나란히 보기)**: "화면 배치" 상자(자동/나란히/위아래, localStorage). 자동은 오른쪽 화면 `ResizeObserver` 폭 ≥ 1280px 이면 `grid 1.3fr : 1fr`, 편집기는 왼쪽·페이지 배치는 오른쪽 `sticky`(높이 제한 `(100vh-170px)×용지 비율`). 안내 문구의 "아래/위쪽"도 배치에 맞게 바뀜. 1900×1000 창에서 확인.
- **페이지 제목 바로 고치기**: `composePage` 가 제목·소제목 자리(`slots`: rect mm, has, text)와 칸 제목 자리(`capRect`, `captionText`)를 돌려준다. 미리보기 위 투명 자리(`.pg-slot`, 마우스를 올리면 주황 점선, 비어 있으면 "＋ 제목 추가")를 누르면 `InlineInput` 이 열린다. 제목·소제목은 한 번 클릭, 칸 제목은 더블클릭(칸을 끄는 동작과 겹치지 않게). 한 칸 페이지에서 제목이 그림 제목(spec.title)에서 온 것이면 비울 때 그쪽도 비움. 칸 제목 수정은 `pushHistory` 로 페이지 되돌리기에 들어가고, 고른 칸은 `result` 를 고쳐 effect 가 `cells` 로 옮기게 함(`cells` 만 고치면 effect 가 옛 `result` 로 덮어쓴다).
- **글자 위계 경고**: `judgeTextPt(pt, tiers)`(page.js 순수 함수) — 최소 크기 미만 ⚠(인쇄 7pt/화면 11pt), 칸 제목·소제목·제목 이상 ⚠, 가장 가까운 단계의 ±12% 안이면 ✔, 그 밖은 ℹ + 맞출 pt. `PtReadout` 이 pt 아래에 색 상자로 보여 주고, 구조형 글자·손스케치 메모는 "N pt로 맞추기" 버튼(`onFix`)으로 바로 맞춤(레이어 확대 배율·글자 맞춤 배율을 거꾸로 환산). 윗 위계는 그 칸에 실제 붙는 칸 제목 → 소제목 → 제목 순.
- **시험**: check_diagrams 324 → 349개(위계 판정 경계·제목/칸 제목 자리, 자르기 제자리·해제·재자르기, 바꾸기 비율·중심, 여러 장 비껴 놓기, 구조형 adds, orig/crop 비유출, href 없는 호출 방어). 실제 ConceptDiagram 부품에서: 붙여넣기(입력칸 무시·빈 화면 채움·여러 장 얹기·이미지 우선·글자만 있으면 편집기 복사 붙임), 이미지 바꾸기(비율 4.00·중심 유지)·자르기(좌표 정확)·해제·되돌리기·Esc·창 열린 동안 Delete 무시(손스케치·구조형 양쪽), 페이지 모드 2×2에 3장 끌어다 놓기(칸 2·3·4 채움)·그림 있는 칸 얹기, 제목·칸 제목 인라인 수정, 위계 경고와 "8pt로 맞추기", 화질 3단계(3200×2000 → 1000/1600/2600px, 165/343/614KB), 나란히 보기.
- **한계**: 클립보드 이미지는 브라우저가 주는 첫 형식만 읽음(여러 장 동시 복사는 환경에 따라 1장). 칸 제목이 없는 칸에 새로 붙이는 입력은 없음(그림 제목을 고치면 생김). 나란히 보기는 오른쪽 화면이 좁으면(<1280px) 자동으로는 안 켜지고, 직접 고르면 좁은 화면에서 편집기가 빽빽해질 수 있음. 자르기의 원본은 작업 중에만 보관(저장 파일엔 자른 그림만).

## 19. 서버가 가끔 꺼지는 문제 — 원인 조사와 해결 (사용자: "서버가 가끔 꺼지는 문제는 해결해줘")

- **범위(인터뷰 결정)**: 라벨–값 표 · 2~4열 · 두 스타일(회색 라벨 열+가는 선 / 색 띠+줄무늬) · 열 너비는 글자 길이에 자동 · 편집은 속성 패널 행 목록 + 그림에서 셀 더블클릭. 병합 셀·계산·간트는 제외. v2(엑셀·한글 붙여넣기 변환, 페이지 칸 전용 표)는 R8.
- **모듈** `conceptDiagram/table.js`: `normalizeTable`(열 2~4·모든 행 칸 수 일치·글자 40자·제목 40자·행 30개·줄바꿈 제거·모르는 스타일은 라벨형), 편집 도우미 `tableSetCell/AddRow/DelRow/MoveRow/SetCols`(모두 새 표를 돌려줌), `tableLayout`(열 너비 = 그 열 글자 폭 최댓값 + 좌우 여백, 제목이 더 길면 마지막 열을 넓힘, 행 높이 = 글자×2.0), `tableSvg`(라벨형: 제목 굵게 + 아래 선, 라벨 열 `#EDEDED`, 행 사이 가는 선, 위·아래 굵은 선 / 줄무늬형: 제목 색 띠 + 연한 줄무늬 + 바깥 테두리 + 숫자·단위 값 오른쪽 맞춤). 편집 화면에서만 표 전체와 셀마다 투명 `data-cell="행,열"` 사각형(제목 `-1,0`, 빈 칸 포함)을 더해 선택·더블클릭에 쓴다(저장용 그림에는 없음).
- **두 편집기 연결**: 손스케치는 `memos[].table`(x, y = 표 왼쪽 위, `size` = 글자 크기, `color` = 띠·선 색, 회전 없음, `sketchAdd('table')`, `sketchApplyText` 의 `{tableId, r, c}` 로 셀 고치기), 구조형은 `adds` 의 `kind:'table'`(`x,y,size,fill,table`, `editAddTable`, 묶음 회전 때만 자리 이동). 셀 더블클릭은 `[data-cell]` 을 먼저 보고(글자 위치 찾기보다 앞), 입력칸은 그 셀 사각형 자리에 뜬다. 새 `TableEditor.jsx`(제목·열 수·스타일·행 목록)를 두 속성 패널에 공통으로 쓰고 키(`cell:i,j`)로 되돌리기 묶음을 만든다.
- **범위 안내(R2) 문구**: 표 카테고리 설명을 "단순 개요표는 편집기 ＋ 표로 직접 넣어 고칠 수 있음(병합·계산·간트는 불가)"로 고침.
- **시험**: check_diagrams 592 → 635개(정리·한도·편집 도우미 불변성·열 늘리고 줄이기·배치 계산·두 스타일 그리기·특수문자·빈 표·셀 눌림 영역·손스케치/구조형 추가·저장·불러오기·셀·제목 고치기·옮기기·붙여넣기·회전 제외·저장용 그림에 편집 표시 없음). Edge 로 라벨형 2열·줄무늬형 3열·4열(라벨 열 2개)·작은 글자 표를 그려 모양 확인(4열일 때 셋째 열도 라벨 열로 고침). 시험 화면(5181)에서 두 편집기 모두 ＋ 표 → 셀 입력 → 행 추가·삭제·열 수·스타일·크기 → 셀·제목 더블클릭(빈 칸 포함) → 끌어 옮기기를 눌러 확인.

## 27. 바탕 흐리게 (R6) — 내 이미지 탈색·가장자리 흐리게·맥락 바탕 한 번에 (인터뷰 결정 6: "내 이미지를 바탕으로 흐리게(탈색+투명도), 이미 있는 '내 이미지 넣기' 재사용")
- **설계**: 래스터를 새로 구워 원본을 잃지 않고 **SVG 필터·마스크로 겹쳐 그린다**(결과를 계속 편집할 수 있어야 한다는 원칙). 새 모듈 `conceptDiagram/imgfx.js` 의 `imageFx(id, {x,y,w,h,gray,edge})` 가 `{ defs, attrs }` 를 돌려준다 — 탈색은 `<feColorMatrix type="saturate" values="1 - gray/100">`(필터 `fxg_<id>`), 가장자리는 이미지 자리(userSpaceOnUse)에 **안쪽으로 들인 흰 사각형을 가우시안으로 흐리게** 한 마스크(`fxm_<id>`; 띠 너비 = 짧은 변 × 25% × edge/100, 들임 0.9띠, σ 0.4띠 → 가장자리 투명·안쪽으로 서서히 진해짐). 둘 다 0 이면 아무것도 더하지 않아 예전 결과와 바이트까지 같다. 돌린 이미지는 마스크가 같은 변환 좌표에서 적용된다.
- **연결**: 손스케치 `blocks[kind:'image']` 에 `gray·edge`(0~100 정수로 정리, `clampPct`), `imgSvg` 가 정의를 앞에 붙이고 `<image>` 에 `filter·mask` 속성. 구조형 `adds[kind:'image']` 에 `gray·edge`, `imgTag`(이미지 한 조각을 함수로 뺌). 정의 id 는 `id="…"`/`url(#…)` 형태라 페이지 모드의 `scopeIds` 가 칸마다 접두어를 붙여 여러 칸이 서로 덮어쓰지 않는다.
- **UI**: 두 편집기 이미지 속성에 **탈색 / 가장자리 흐리게** 슬라이더, **🌫 맥락 바탕으로 흐리게**(`CONTEXT_FX`: 탈색 100 · 투명도 0.35 · 가장자리 0 · 맨 뒤로), **효과 지우기**(효과가 있을 때만 표시). 투명도·앞뒤는 기존 것 그대로.
- **시험**: check_diagrams 635 → 655개(범위 정리·효과 판정·기본값·필터/마스크 문자열·아주 작은 이미지·특수문자 id, 손스케치 저장·불러오기·범위 밖 값·돌린 이미지·편집 화면 손잡이, 구조형 필터·마스크 부착·저장용 그림에 편집 표시 없음·맨 뒤 이미지에서 정의 위치·효과 든 결과 재읽기). Edge 로 원본/탈색/맥락 바탕(위에 파란 매스)/가장자리 70% 네 장을 그려 눈으로 확인. 시험 화면(5181)에서 두 편집기 모두 슬라이더→필터·마스크 속성 반영→맥락 단추(탈색 100·투명도 0.35·맨 뒤)→효과 지우기를 눌러 확인(구조형은 실제 이미지 파일 입력으로 넣어 시험).
- **한계·메모**: 필터·마스크는 브라우저·PNG 저장에서 잘 보이고 일러스트레이터에서는 SVG 필터 효과로 열린다(래스터로 굽고 싶으면 PNG 저장). 페이지 칸 배경 이미지·칸 전체 흐리게는 이번 범위가 아니다(내 이미지 요소 기준). 투명도 슬라이더 하한은 5% 그대로.
