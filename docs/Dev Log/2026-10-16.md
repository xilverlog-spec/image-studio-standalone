## 1. 유료 API 누적 총 한도 10,000원
- 요청: 유료 API 전체 총 리밋을 10,000원으로. 기존에는 하루 한도(USD)만 있었음.
- 구현: `backend/config.py` 에 `PAID_TOTAL_LIMIT_KRW`(기본 10000)·`USD_KRW`(환율 가정, 기본 1400원/$) 추가, 정밀 읽기 예상 비용 기본값 $0.03 → $0.07(상위 모델의 생각 토큰을 고려한 추정). `backend/services/paid_image.py` 장부(data/paid_usage.json)에 날짜 기록과 별도로 `_total` 누적 합계를 저장(40일 지난 날짜 기록을 지워도 합계는 유지)하고, 이미지 생성·정밀 읽기 등 모든 유료 호출 전에 누적 총 한도(원)를 먼저 검사해 넘기면 사유와 함께 막음. 조감도 화면과 정밀 읽기 확인창에 누적 사용액·총 한도·남은 금액을 원화로 표시. `backend/.env` 에 같은 값을 명시(키는 건드리지 않음).
- 시험: check_fast.py 에 한도 시험 추가(누적 합산·원화 환산·한도 초과 차단·한도 0 이면 검사 안 함), 서버 재시작 후 `/v1/image/options` 가 total_limit_krw 10000, remaining_krw 10000 을 돌려줌.
- 주의: 한도는 코드의 '예상 비용'(대략치) 기준이라 실제 청구액과 다를 수 있음 → Google Cloud·OpenAI 쪽 예산 알림을 같이 걸어 둘 것. 앞으로 만들 유료 경로(분석 축측도 이미지 생성, 축측도 AI 단계, 손스케치 이름 붙이기)도 반드시 같은 장부(check_budget_amount / record_usage_amount)를 거쳐야 함.

## 2. 유료 경로 3곳 미리 만들기 (키 연결 전, 사용자 요청)
- 만든 것(모두 키가 없으면 버튼이 화면에 안 보임, 누를 때만 호출, 확인창에 예상 비용(원)과 누적 사용액 표시, 서버가 누적 총 한도 10,000원을 검사하고 장부에 합산):
  ① 분석 축측도 **유료 이미지 생성**: 지금 결과(글자 뺀 초안) + 내 도면 + 참고 이미지를 `/v1/image/generate`(provider openai/gemini, 3:2, 외부 전송 동의)로 보내 새로 그리게 하고, 그림을 바탕으로 쓰고 문구 블록은 편집 가능한 글자로 얹음(프롬프트에 '글자 넣지 말 것·오른쪽 30% 비움'). '벡터 버전으로 되돌리기' 제공.
  ② 분석 축측도 **AI 단계 유료**(바람·일조·문구 정하기): `callAI(..., {paid:true})` → paid_vision(상위 Gemini). 실패하면 무료로 몰래 바꾸지 않고 사유를 보여 줌.
  ③ 손스케치 **이름·설명·바람 방향 붙이기 유료**: 같은 방식.
- 시험(키 없이 서버 응답을 흉내 낸 임시 시험 페이지, 실제 앱 화면 컴포넌트): 유료 상자와 두 버튼 표시, ② 요청에 paid:true·이미지 2장, ① 요청에 provider·3:2·동의·초안·도면+참고·'글자 금지' 프롬프트, 결과가 바탕(이미지)+편집 가능한 문구로 적용되고 되돌리기가 바람 띠를 복구, ③ 요청에 paid:true(이미지 없음), 키가 없으면 상자 전체가 숨음(분석 축측도·손스케치 모두). 실제 유료 서버 호출은 키가 없어 하지 못함 → 연결 후 첫 호출에서 확인 필요(공급자별 이미지 입력 형식 등).
- 남은 것: 키 연결 후 무료 Flash 대 유료 Gemini, 유료 이미지 생성 결과 비교와 실제 비용 대조(코드의 예상 비용을 실측값으로 보정).
