## 3. 1단계: 이미지 종류 자동 판단 (사용자 지적: 종류를 매번 고르는 건 복잡하고, 다이어그램이 조금만 달라져도 모드가 맞지 않는다)
- 방향(승인): 모드 선택 → '부품 조합' 구조로. 1단계 = 사용자가 종류를 고르지 않고 AI가 판단해 알맞은 읽기 방식으로 보냄. (2단계: 참고 이미지를 읽어 부품 조합을 정함, 3단계: 부품 목록 정리·추가)
- 구현: subject.js 에 `buildSubjectClassifyPrompt`/`normalizeSubjectType`/`routeSubject`(손스케치→sketch, 입체 그림→freeform, 건물 사진→form, 배치도→site, 평면도→참고 이미지나 분석 단서(바람·통풍·환기·일조·채광·남향·조망…)가 있으면 axon 아니면 plan, 모르면 freeform). ConceptDiagram 의 readImage 가 종류가 '자동'이면 무료 AI 1회로 판단(같은 그림은 `cls:` 키로 저장), 판단 결과를 화면 줄과 알림으로 알림. 분석 축측도로 갔는데 벽 추출이 안 되면(평면도가 아님) 이유를 알리고 평면 다이어그램으로 대체. 참고 이미지를 나중에 넣으면 평면도 판단을 다시 함. 화면: 이미지 종류 선택은 '직접 지정'으로 접고(기본 자동), 옵션·안내·유료 상자는 '지금 적용되는 종류'(effKind) 기준으로 표시.
- 시험: 규칙 단위 시험(경로 매핑·분석 단서·이상한 응답, check_diagrams 50개), 실제 화면 부품에 분류 응답을 흉내 내서 5경로 확인 — 평면도+참고→분석 축측도, 참고 없고 단서 없는 설명→평면 다이어그램, 평면도로 오판된 스케치 사진→벽 추출 실패를 알리고 평면 다이어그램으로 대체, 손스케치→손스케치 읽기(3회 읽기+보정), 입체 그림→자유 해석. 분류 저장, 이미지 교체 시 판단 초기화, 직접 지정 접힘 확인.
- 시험 중 발견·수정: ① 새로 넣은 `effKind` 줄이 `read` 상태 선언보다 먼저 실행돼 화면이 아예 뜨지 않는 오류(빌드는 통과하지만 실행 시 오류) → 선언 순서 수정. 잠시 배포본(`index-?`)에 이 오류가 있었음, 곧바로 수정본 재배포. ② 백엔드(5000)가 조용히 종료돼 있어 재시작 — 도구 세션에서 띄운 프로세스가 세션 정리 때 같이 죽는 것으로 추정. 작업 스케줄러 `ImageStudio-Backend` 를 시작해 보니 결과 코드 1 로 즉시 실패(원인 미확인) → 자동 복구 경로가 아직 믿을 수 없음. 수동으로 python.exe(숨김)로 다시 띄움.
- 한계: 자동 판단은 AI 분류 1회에 의존(무료 한도 429 이면 예전 자동 읽기로 대체), 평면도 → 분석 축측도/평면 다이어그램 갈림은 단서 단어 규칙이라 단서가 없으면 평면 다이어그램으로 간다(직접 지정으로 바꿀 수 있음).

- 사용자 시험: 방 20개가 넘는 연구시설 CAD 평면 + "동선을 표시한 다이어그램" → 자동 판단은 '평면도 → 평면 다이어그램'으로 맞게 갔지만 결과가 "최악"(방 이름이 칸 밖으로 삐져나와 겹침, 구역 이름 글자가 연한 색 위의 흰색이라 안 보임, 동선이 방 중심끼리 곡선으로 이어져 글자를 가로지름, 원본 모양이 3줄 격자로 사라짐). 같은 도면을 GPT 가 "도면 그대로 + 부서별 색 + 복도를 따라가는 동선 + 범례"로 그려 준 그림을 가져와 "이 정도면 만족"이라고 함.
