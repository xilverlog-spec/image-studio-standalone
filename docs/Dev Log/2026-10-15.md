- 확인된 구조 문제 2가지: ① 이전 빌드(보정 알고리즘이 달랐던 때)에 저장된 낡은 읽기 결과가 새 빌드에서도 그대로 재사용됨 ② 그림·설명 식별 해시가 글자를 5개마다 하나만 봐서 서로 다른 그림·설명이 같은 저장값으로 잡힐 수 있음.

- 시험(임시 시험 페이지, 실제 Gemini): 처음 읽기(AI 호출) → 같은 그림 다시 만들기 시 저장 결과 사용+안내+새로 읽기 버튼 활성 → 새로 읽기 누르면 AI 3회+정리 호출로 새로 읽고 안내 사라짐. 확인 못 한 것: 사용자가 본 발코니 그림 자체(파일이 없음), 재현 조건은 추정.

## 2. 이미지 → SVG 변환이 짜글짜글하게 깨지는 문제 (사용자 보고: 연한 회색 면·흐린 그라데이션 화살표·굵은 검정 선 그림)
- 재현(보내준 결과 그림을 원본 대용으로, 가우시안으로 계단을 풀어 사용): '깔끔하게' 모드는 3배 확대+중간값 필터 5+거친 색 단계(5)로 흰 바탕에 가까운 연한 면과 벽이 배경에 먹혀 거의 사라지고, '원본에 가깝게' 모드는 색을 층층이 쪼개 계단 띠·거친 가장자리가 생김. vtracer 는 색이 연속으로 변하는 그림에 약함.
- 구현(backend/services/vector_smooth.py, `/image/vectorize` mode=smooth, 새 기본): ① Lab 색공간 k-평균으로 14개 대표색(흰 바탕 비중을 줄여 연한 색도 살림) ② 대표색마다 영역 경계를 가우시안으로 부드럽게(가는 어두운 선은 가중치로 보존) ③ 평면 색 그림을 vtracer 에 넘김. 화면(DrawioEditor): '부드럽게(권장)' 추가 및 기본 선택, 기존 두 모드 유지.
- 시험: 같은 그림에서 벽·화살표·그라데이션이 모두 남고 가장자리가 깨끗(긴 변 2400px, 3.4초). 평평한 선화(full6.png, 6칸 매스 다이어그램)에서도 '깔끔하게'와 같거나 더 또렷. 색 연속성 점수로 자동 선택하는 안은 이 그림(0.17)과 평평한 그림(0.05~0.14)이 겹쳐 버림 → 항상 부드럽게를 기본으로.
- 주의: 백엔드를 재시작해야 반영됨(사용자가 시험 중이라 아직 재시작하지 않음). 실제 원본 파일은 없어서 보내준 결과 그림으로 재현함 → 원본으로 최종 확인 필요.

## 3. SVG 변환 수정 정정 — 실제로 쓰는 화면은 '선 추출(LineTrace)'
- 오류: 위 2번의 '부드럽게'를 draw.io 탭(DrawioEditor)의 변환에 넣었는데, 그 화면은 `DiagramModule.jsx` 에서 이미 빼 둔(파일만 남은) 기능이라 화면에 나오지 않았다. 사용자가 "부드럽게 모드가 없다"고 알려 확인. 빌드 산출물에도 그 문구가 없었음(미사용 컴포넌트라 번들에 포함되지 않음).
- 실제 경로: 다이어그램 탭 '선 추출(LineTrace)' → `/image/linetrace/start` → `line_pipeline._run_color` → `diagram_kind.vectorize_color`. 여기에 `smooth` 옵션을 끝까지 연결(요청 필드 smooth → start_job → _run_color → vectorize_color(smooth)), 화면 '고급'에 **색 면 도식 변환 스타일: 정밀(기존, 기본) / 부드럽게(새 방식)** 추가.
- 기본값을 '정밀'로 둔 이유: 재현에 쓴 그림이 이미 한 번 변환된 결과물이라 원래 문제를 정확히 재현하지 못했고, 같은 그림에서 기존 방식이 그라데이션 번짐을 더 자연스럽게 살리는 면도 있었음(새 방식은 띠가 보임). 평면도는 둘이 비슷(새 방식은 바닥 질감이 평평해짐). 사용자가 원본으로 두 스타일을 비교해 알려 주기로 함.
- 시험: 실제 서버에서 같은 그림으로 precise(2.0초, 경로 1266개) / smooth(5.1초, 경로 498개) 모두 완료.

## 4. SVG 변환 '부드럽게'를 메인 화면으로 + 대체 경로 연결 (사용자 화면 확인)
- 사용자 화면: 이 그림(입체 평면 + 그라데이션 화살표 + 문구)이 자동 판별로 '원근 캡처·렌더 → AI(FLUX Kontext)가 선화로 다시 그리는 중(약 3분)' 경로로 감. 그 경로에서 AI 재생성을 못 쓰면 색 영역 변환으로 대체되는데, 이 대체 변환에 smooth 가 전달되지 않았음 → 짜글짜글한 결과의 실제 원인 후보. `_run_perspective(…, smooth)` 로 연결(백엔드 재시작 필요 — 사용자 변환 중이라 대기).
- 화면: '색 그림 변환 스타일(정밀/부드럽게)'을 '고급' 안에서 메인 화면으로 꺼냄. '부드럽게'를 고르면 변환 방식을 '색 면 도식'으로 자동 전환(선 도식·원근 캡처에는 적용되지 않음을 안내).
- 시험(임시 시험 페이지에서 실제 앱 화면 컴포넌트): 메인에 박스 표시, 부드럽게 선택 시 method=color 자동, 요청 본문 {method:'color', smooth:true}, 6초에 변환 완료.

## 5. 분석 축측도 (사용자 승인: 내 평면도 + 참고 이미지 → 입체 바탕 + 바람·일조 + 문구)
- 원인(사용자 보고 결과가 참고와 달랐던 이유): 평면 기반 다이어그램은 납작한 2D 도형에 화살표·해칭만 얹는 구조라 입체 바탕·바람 번짐 띠·일조 호·문구 블록을 그릴 수 없었고, AI 는 그릴 수 있는 것(구역·동선 두 칸)만 골랐음. 개념 문장이 없으면 AI 가 임의로 정함. 평면 읽기도 거칠어 방 이름이 줄고 내부 벽이 사라짐.
- 구현 ① backend/services/plan_axon.py + `/image/plan-axon`: 평면 도면에서 굵은 검정 벽·회색 벽선·바닥 외곽을 이미지로 직접 뽑아(구멍 있는 다각형) 낮은 벽으로 세운 축측 SVG(AI 없음, 0.7초). 평면 좌표→화면 변환(proj)도 돌려줌. 벽이 아닌 그림(블록 다이어그램·사진·스케치·배치도·입체 수채)은 뼈대 길이(긴 변의 1.0배 미만)·흰 여백(12% 미만) 기준으로 거절하고 이유를 알림(시험: 평면도만 통과, 6종 비평면 모두 거절).
- 구현 ② sketch.js/SketchEditor: spec 에 base(입체 바탕, 선택·끌기 안 됨), textBlock(제목·밑줄·▼·부제), 글자 메모 icon 'sun', layout 'axon'(흰 바탕). AI 는 바람(from→to), 일조 호(from/via/to), 제목·부제, '참고 이미지에서 읽은 구성/못 그리는 것'만 JSON 으로 정하고 코드가 번짐 띠(soft)·점선 호(양쪽 화살촉)·해 아이콘으로 그림. 모두 편집기에서 끌어 고칠 수 있음, 문구 블록 편집 칸 추가.
- 구현 ③ 화면: 이미지 종류 '분석 축측도', 남쪽 방향·벽 높이·시점 선택, 참고 이미지에서 읽은 구성 안내, 개념 문장이 비었을 때 경고(참고 이미지가 있을 때 포함).
- 시험: 사용자의 평면도 + 참고 이미지 + "전 세대 남향배치로 채광을 확보하고 맞통풍과 수변조망을 극대화" → 입체 평면 + 바람 띠 4개 + 일조 호·해 + 오른쪽 문구 블록, 6초. 앱 화면 컴포넌트에서 미리 읽기(입체 바탕)와 만들기 모두 동작 확인. 회귀: check_diagrams 38개, check_fast 전체 통과(축측 합성 평면·거절 시험 포함).
- 한계: 평면 도면이 CAD처럼 벽이 굵은 선으로 깨끗해야 함(시험 평면 1장뿐), 가구선·창 구분 없음, 바람·일조 위치는 AI 눈대중(편집으로 보정), 남쪽 방향은 사용자가 지정.

## 6. 부드럽게 = '선 + 색 분리 변환'으로 교체, 분석 축측도에 바닥 질감 (사용자 보고: 부드럽게가 달라진 게 없다 / GPT 결과가 훨씬 낫다)
- 사용자 화면의 실제 경로 확인: 자동 판별이 '원근 캡처·렌더 → AI(FLUX Kontext)가 선화로 다시 그림'으로 가서 AI 재생성은 성공(선이 깨끗)했지만 **색(노란 바람 띠·해)이 모두 사라지고 그림이 잘림**(왼쪽 건물, 오른쪽 문구 "및/극대/채광") — AI 가 새로 그린 그림이라 색·구성이 바뀌는 것이 이 경로의 한계.
- 기존 '부드럽게'(색 묶기+경계 부드럽게, 확대 비교)는 기존 대비 차이가 분명하지만 일반 크기에선 작아 보였고, 더 세게 하면 벽 구조가 뭉개져 중간 단계가 없었음.
- 새 방식(vector_smooth.vectorize_hybrid): 선은 선대로, 색은 색대로 따로 변환해 겹침 — ① 선: 어두운 화소 + 거기에 이어진 가는 선 화소(블랙 탑햇, 히스테리시스)를 흐렸다 다시 잘라 부드러운 윤곽으로 이진 변환 ② 색: 선 자리를 가까운 밝은 색으로 메우고 10색으로 묶어 경계를 부드럽게 변환 ③ 색 위에 선. 원본에서 직접 따므로 구성·색·글자 위치가 안 바뀜. 시험: 41번 그림(선 깨끗·색 유지·문구 선명), 선 위주 도식(full6: 글자 'ADD TION' 깨짐 → 'ADDITION' 정상, 가는 선 복구), CAD 평면(작은 한글 글자는 기존 수준, 굵은 벽 선명). 시험 중 가는 선이 점선처럼 끊기는 문제(흐림 σ1.1·문턱 0.42)를 σ0.6·0.36·이어붙이기로 해결.
- 분석 축측도: 사용자가 같은 도면·참고로 GPT(이미지 생성)에 시험해 가구·바닥 질감이 보이는 훨씬 풍부한 그림을 얻음. 우리 결과는 벽만 세운 회색 모형이라 밋밋 → 원본 도면 그림을 입체 바닥에 그대로 입힘(평면→화면 변환이 아핀이라 <image> 행렬 하나, 바닥 외곽으로 잘라냄). 기본 켬, 화면에 끄기 체크. 긴 제목은 글자 크기를 줄여 칸 안에 맞춤(시험 중 '극대화'가 잘려 발견).
- 비교(정직하게): GPT 는 래스터로 처음부터 새로 그리므로 질감·가구 입체가 더 매끈하지만 벡터·편집 불가이고 도면과 글자를 바꿀 수 있음(실제 결과에서 문구가 달라짐). 우리 방식은 도면의 벽·방 이름이 정확하고 모두 편집 가능한 SVG. 더 근접하려면 유료 이미지 생성(키 연결 시 선택)을 보조로 붙이는 안이 있음.
