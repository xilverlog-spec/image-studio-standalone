# 2026-10-12

> 자동 일지 생성이 claude 로그인 문제로 멈춰서 직접 작성했습니다.

## 오늘의 목표
유료 API를 연결하기 전에 남은 일을 끝낸다. 조감도에서는 참조 이미지가 있을 때도 짧은 지시문이 나은지 확인하고, 다이어그램 만들기에서는 만들어 두고 연결하지 않았던 두 종류와 평면 라벨 겹침을 마무리한다.

---

## 1. 조감도: 참조 이미지가 있을 때의 지시문
**왜 필요한가**: 지난번에 참조 이미지가 없을 때만 짧은 지시문으로 바꿨다. 참조를 넣는 경우(레퍼런스 모드, 이지 다중 첨부)는 여전히 1,300~2,100자의 긴 지시문이라, 같은 방식이 통하는지 확인해야 했다.

**수정**: 참조용 짧은 지시문(`kontext_short_ref`)을 만들었다. "이미지 1은 원본, 이미지 2~는 참조"로 부르고, 참조에서는 표면(재료·리듬)·조명·주변만 가져오고 건물 형태는 가져오지 않는다고 한 문장으로 못 박는다. 참조별 역할·"가져올 것"·분석 요약을 생성 요청에 함께 보낸다. 사용자가 프롬프트를 직접 고쳤을 때는 짧은 지시문이 그 수정을 무시하지 않게 긴 방식으로 보낸다.

**시험**: 같은 시드로 긴/짧은 지시문을 비교했다.
- 1-1 공장 + 노출콘크리트(새로 제안 / 그대로 입히기): 두 결과가 눈으로 구분되지 않았다. 둘 다 콘크리트 외장은 약하게만 반영됐다. 멀리 있는 큰 건물에 작은 참조 사진을 입히는 조합이라 모델 한계로 보인다.
- ALT3 카페 + 적벽돌 참조(새로 제안): **긴 지시문은 참조 건물의 모양을 통째로 베껴** ALT3 대신 붉은 벽돌 3층 상자를 만들었다(형태 점수 0). **짧은 지시문은 ALT3의 곡선 매스와 지붕 루버를 지키고 벽돌색만 입혔다.**

**결과와 원인**: 긴 지시문에 참조 건물 묘사가 많이 들어가 모델이 그 건물을 그리는 쪽으로 끌려간 것으로 보인다.

**수정 후 재시험**: 참조 이미지가 있어도 짧은 지시문을 기본으로 바꿨다. 기본 경로로 참조 1장(적벽돌)과 2장(입면+재질)을 다시 돌려 둘 다 형태가 유지되고 재료만 입혀지는 것을 확인했다. 분석 요약이 문장 중간에서 잘리는 문제도 문장 단위로 자르게 고쳤다.

## 2. 다이어그램 만들기: 프로그램 버블도·층별 조닝도 연결
**왜 필요한가**: `program.js`, `stack.js`가 만들어져 있었지만 종류 목록에 없어 화면에서 쓸 수 없었다.

**수정**: 종류 목록, AI 프롬프트(스키마·규칙), 정규화, 글자 수정, 예시를 연결했다. "자동" 선택에서 AI가 4가지 종류(배치·매스·프로그램·조닝) 중 고른다.

**시험**: 실제 Gemini로 세 요청을 넣었다. 도서관 층별 구성은 조닝도, 문화센터 공간 관계는 버블도, 마을 광장 흐름은 기존 배치 개념도로 정확히 골랐고 모두 그려졌다.

**눈으로 본 문제와 수정**
- 조닝도: 층 칸의 이름이 칸 정중앙에 놓여 보이드·코어에 가려졌다(4F 라운지가 안 보임). → 칸에서 보이드·코어를 뺀 가장 넓은 빈 구간에 놓고, 좁으면 글자를 줄이거나 줄임표로 바꾼다.
- 버블도: 같은 묶음 안의 원이 붙어 연결선이 안 보였고, 연결이 많으면 라벨이 원 위에 얹히고 묶음 이름이 선에 가려졌다. → 묶음 간격을 넓히고 글자를 흰 테두리로 맨 위에 그리며, 짧은 선·원 위 라벨은 생략한다.
- **남은 한계**: 연결이 많으면 선이 다른 원을 지나가고, 라벨이 묶음 이름과 겹치는 곳이 한두 군데 남는다.

## 3. 평면 라벨 겹침
**왜 필요한가**: 평면 개념도에서 방 이름·구역 이름표·주석 상자가 서로 가렸다.

**수정**: 이미 놓인 라벨 상자를 기억해 겹치면 다른 후보 위치(위/아래, 좌우)로 옮기고, 방 이름은 글자를 줄이거나 비켜 놓는다. 끝내 못 놓으면 생략한다.

**시험**: 작은 방이 붙은 합성 평면으로 전후를 비교해, 이름표끼리 겹치던 것과 주석 상자가 이름표를 가리던 것이 해결된 것을 확인했다.

## 4. 손스케치 → 다이어그램 + 바로 고치기 (1단계 편집)
**왜 필요한가**: 설계자가 손으로 그린 개념 스케치(예: 판상형 + 맞통풍)를 정돈된 다이어그램 소스로 만들고, 화살표 표시·선 종류 같은 간단한 것은 바로 고쳐서 SVG로 받고 싶다.

**시험과 결과**: 지금 앱의 이미지 읽기에 넣어 보니 손스케치를 "방 7개짜리 평면도"로 읽어 없는 이름을 지어냈고, 판상형 띠와 물결선을 놓쳤다. 읽기 방식이 방 단위 평면도를 전제로 만들어졌기 때문이다.

**수정**: "해석하지 말고 그려진 도형을 있는 그대로" 읽는 손스케치 전용 읽기(상자·빗금 채움·자유 곡선)를 만들었다. 가까운 모서리를 맞추고 칸막이를 반듯하게 정리하며, 요청 문장을 얹어 이름·설명·바람 방향만 AI가 정한다(도형 위치는 못 바꿈). 번호 표식 + 우측 설명 칼럼으로 이름표 겹침을 없앴고, 바람은 굵은 띠 + 유입/유출 표시로 그렸다(처음엔 발표용·도면용 2종이었으나 사용자가 발표용은 필요 없다고 해서 도면용 하나로 통일).

**1단계 편집**: 구조(spec)를 코드가 그리는 방식이라 화면에서 요소를 클릭하면 속성(화살촉 방향, 실선/파선/점선, 굵기, 색, 글자, 위치)을 바꾸고 즉시 다시 그린다. 요소 추가·삭제, 방향 뒤집기, 되돌리기(Ctrl+Z), SVG·PNG 저장(저장본에는 편집용 속성을 넣지 않음)을 넣었다.

**재시험**: 브라우저에서 실제로 읽기→생성→클릭 선택→화살촉 양쪽→점선→뒤집기→되돌리기→화살표 추가·끝점 이동→글자 메모 추가·삭제→Delete 키→도면용 전환→SVG 저장까지 확인했다. 회귀 점검에 손스케치 렌더·편집 함수 6건을 추가했다(전체 22건 통과).

**참고 그림을 보고 선 표현 확장**: 사용자가 가져온 참고 다이어그램은 맞통풍이 S자로 휘어 창을 통과하는 부드러운 푸른 리본이고 벽에는 점선 캡슐(개구부)이 있었다. 우리 결과는 가는 선이 손떨림 그대로 구불거려 부자연스러웠다.
- **곡선**: 읽은 선을 Chaikin 으로 다듬어 9점으로 다시 뽑고(손떨림 제거), 곡선 모양(읽은 모양/S자/호/직선)과 세기·휘는 정도를 속성으로 조절하게 했다.
- **선 표현**: 실선·파선·점선에 일점쇄선, 이중선, 리본(끝이 가늘어지는 붓 띠), 번짐(끝이 흐려지는 그라데이션 띠), 화살표 반복, 물결 장식선을 추가했다. 기본은 리본이다.
- **개구부**: 점선 캡슐 도형과 범례를 추가했다.
- **시행착오**: 물결 장식선이 울퉁불퉁했다(중심선의 점에 붙여 계산해 계단이 생김) → 호 길이를 따라 보간하게 고쳤다. 화살표 반복은 끝 화살촉과 떨어져서 간격을 고르게 나눴다.
- **재시험**: 6표현 × 4모양 × 4화살촉 × 2스타일 전 조합과 개구부·길이 0인 선이 깨지지 않는지 회귀 점검에 넣었다(25건 통과). 브라우저에서 선 표현·곡선 모양·휘는 정도·개구부 추가·SVG 저장을 눌러 확인했다.

**리본이 불꽃 모양으로 어색하다는 지적과 끌기 편집(2단계)**: 첫 리본은 끝이 뾰족한 가는 띠라 불꽃처럼 보였다. 양 끝도 일정 폭(0.42)을 남기고 가운데가 가장 넓게, 끝은 투명도 그라데이션으로 흐려지게 다시 만들고 기본 곡선을 S자로 바꿨다. 이어서 그림 안 직접 조작을 넣었다: 끌어서 이동, 8방향 크기 조절점, 화살표 끝점(동그라미) 조절, 다른 도형 모서리에 자석 맞춤, Shift 수평·수직 고정, Alt 자석 끄기, 방향키 미세 이동. 한 번 끈 것은 되돌리기 한 칸으로 묶인다. 사용자 요청으로 발표용 스타일은 빼고 도면용 하나로 통일했다.
**시행착오**: 브라우저 시험 창이 279px 로 좁아 그림 영역 폭이 0 이 되어 좌표 변환이 깨졌다 → 폭 0 이면 끌기를 무시하고 그림 영역에 최소 폭(360px)을 줬다. 스타일 정리 중 같은 줄에 넣은 주석이 뒷부분 코드를 주석 처리해 렌더가 깨졌는데 회귀 점검이 잡아냈다.
**변곡점 이동 요청**: 사용자가 곡선 위 마름모로 "변곡점의 위치를 옮기고 싶다"고 했다. 당시 마름모는 곡선에 수직인 방향의 휨 정도만 조절해서 곡선을 따라 좌우로 끌어도 반응이 없었다. S자를 기본 S자의 가운데 점(변곡점)과 그 점의 진행 방향, 시작·끝 방향을 유지한 두 구간의 곡선으로 다시 계산하게 해서, 큰 마름모를 자유롭게 끌면 곡선이 그 점을 지나도록 했다. 휘는 정도는 작은 빈 마름모로 분리했다. 변곡점을 옮기지 않으면 모양은 기존 S자와 똑같다. 통째 이동·끝점 이동 때는 변곡점도 같은 비율로 따라간다. 점검 시험이 끝점이 겹친 객체를 재사용해 한 번 실패했으나 구현이 아니라 시험 문제였다(깨끗한 객체로 고침).
**재시험**: 브라우저에서 이동(+40px → 그림 좌표 +69, 배율과 일치)·크기 조절·끝점·큰/작은 마름모·Shift·방향키·되돌리기·저장 SVG(조절점 미포함)를 확인했다. 회귀 26건 통과.

**리본 끝 마무리**: 화살촉을 없앴을 때 리본 끝이 일정한 폭을 남긴 채 일직선으로 잘려 보인다는 지적이 있었다(끝 폭을 0.42 로 남기게 만든 설계 탓). 화살촉이 없는 끝은 반원(캡)으로 폭이 0 이 되도록 하고, 중심선을 2.5px 간격으로 촘촘히 다시 뽑아 각져 보이지 않게 했다. 화살촉이 있는 쪽은 그대로다.

**복사·붙여넣기 요청과 단축키 포커스 버그**: 사용자가 Ctrl+C/Ctrl+V 가 안 된다고 했다. 복사 기능이 없었던 것 외에, 더 근본적인 문제를 찾았다. 키보드 단축키(Delete, Ctrl+Z, 방향키)를 편집기 `div` 의 포커스에 의존해 받고 있었는데, 그림을 클릭할 때 기본 동작을 막아 포커스가 옮겨지지 않아서 **실제 사용에서는 단축키가 거의 안 먹었다**(내 시험은 `div` 에 키 이벤트를 직접 보내서 이 문제가 안 드러났다). 단축키를 창 단위로 받도록 바꾸고(입력칸에 글자를 칠 때는 무시), Ctrl+C/V/X/D 를 넣었다. 붙인 요소는 새 id 로 3칸씩 비껴 놓이고 곧바로 선택된다. 이번에는 키 이벤트를 포커스가 없는 `body` 로 보내 실제 사용과 같은 조건에서 확인했다(화살표·도형 복사·붙여넣기·연속 붙여넣기·복제·잘라내기·Delete·Ctrl+Z, 입력칸 보호). 회귀 27건 통과.

**"이전 다이어그램을 기억하는 것 같다"는 제보**: 다른 이미지로 시험했는데 이전 결과가 반영된 듯했다. 원인을 가르려고 완전히 다른 스케치(ㄱ자 매스 + 원 3개 + 화살표, 빗금·물결선 없음)를 직접 그려 읽혔다. 백엔드에는 캐시가 없고, 읽기 단계는 새 그림 그대로 읽었으며(빗금 0·물결 0), 이름 붙이기 단계도 요청이 다르면 이전 용어가 나오지 않았다. 실제 화면 순서(첫 스케치 생성 → 이미지 제거 → 다른 스케치 → 생성)로 재현한 결과, 도형은 새 그림인데 **제목만 "판상형 맞통풍…"** 이었다. 이미지를 바꿔도 **설명칸의 이전 문장이 그대로 남아** 그 문장대로 제목·이름이 붙은 것이 원인이었다(기억이 아니라 남은 입력). 설명을 바꾸자 도형 5개·"업무와 주거의 공존"으로 정상이었다.
- **수정**: 소재 이미지를 바꾸거나 지우면 이전 이미지로 만든 그림을 지우고, 설명이 이전 그림용으로 남았으면 경고와 "설명 지우기" 버튼을 보여 준다. 생성이 실패하면 이전 그림이 그대로 남아 새 결과로 착각할 수 있어 실패 사유를 그림 위에 계속 표시한다("아래 그림은 이전 결과"). 브라우저에서 이미지 제거 시 그림 삭제·경고·지우기·실패 배너를 확인했다.

**두 번째 손스케치가 "너무 다르게 읽힌다"는 제보와 읽기 개선**: 파랑·검정 펜 건물 + 빨간 펜 화살표 6개·호 3개·"OPEN" 글자 3곳·벽에 붙인 빨간 빗금이 있는 스케치(`모델링/2.jpg`)였다. 결과는 화살표가 3개뿐이고 위치·방향이 제각각이었다.
- **원인**: AI는 화살표·호·글자를 눈으로 봤고(요약에 있음) 좌표도 읽었는데, 앱 쪽에서 안쪽 칸막이가 아닌 직선은 버리고 호를 물결선(→ 리본)으로 취급해 왜곡했다. 또 펜 색·글자·벽 표시를 담을 칸이 없었다. 도형 좌표도 부정확했다.
- **시험**: 격자 기준으로 정답을 직접 매겨 도형 겹침(IoU)과 화살표 끝점 오차를 점수로 쟀다. 눈금선을 읽어 좌표를 내는 기존 방식은 **평균 IoU 0.46**(가로 판 0.3)이고 4번 읽어도 같아서(계통 오차) 합의 읽기로는 못 고친다. Gemini 의 기본 위치 표현(상자 [ymin,xmin,ymax,xmax], 점 [y,x]; 0~1000)으로 눈금 없이 읽으면 **0.83~0.87**(세로 판 0.94, 코어 0.9). 다만 한 번씩 세로 판이 0.36 으로 빗나가는 이탈값이 있어 3번 읽어 서로 가장 일치하는 결과를 고른다.
- **수정**: 선을 종류(칸막이/화살표/흐름선/호)와 펜 색으로 읽고, 화살표는 꼬리·화살촉 점(tip)으로 방향을 정하며(처음엔 "pts 를 꼬리→촉 순서로"라고 시켰더니 오히려 거꾸로 적혀 tip 방식으로 바꿨다), 손글씨는 글자 메모로, 벽 표시는 그 벽 위 개구부로, 호는 얇은 곡선으로 가져온다. 이름 붙이기는 읽은 화살표·글자를 바꾸지 않는다. 모델이 화살표 꼬리를 건물 한가운데에 잘못 찍는 일이 잦아, 꼬리가 건물 안이고 화살촉이 건물 밖이면 꼬리를 건물 벽 경계로 자른다.
- **재시험**: 같은 흐름(3번 읽기 → 합의 → 이름 → 그리기)으로 2.jpg 와 첫 스케치(29.jpg) 모두 확인, 브라우저에서도 끝까지 확인했다. 회귀 30건 통과(새 형식·tip 방향·꼬리 정리·합의 시험 추가). AI 가 이름 붙이기에서 가끔 깨진 JSON 을 내는 일시 오류가 있어 앱의 한 번 재시도가 필요함을 다시 확인했다.
- **남은 한계**: 기울어진 판(평행사변형)은 바깥 상자(직사각형)로 단순화된다. 판 안쪽 칸막이 때문에 한 판을 둘로 쪼개 읽는 경우가 있어 직접 합치거나 지워야 한다. 화살표 꼬리는 벽으로 자르는 추정이라 실제와 다를 수 있다. 읽기가 3번 읽기라 1~2분 걸린다.

**참고 개념도 스타일 구현**: 사용자가 "이 손그림은 이런 다이어그램을 생각하고 만든 것"이라며 완성 이미지("3면 발코니세대 최대화")를 보여 줬다. 우리 결과(흰 배경, 번호 표식과 오른쪽 설명 칼럼, 가는 선)와 스타일이 크게 달랐다. 참고 그림의 특징을 코드로 구현했다: 크림 배경, 큰 제목·부제, 흰 판과 굵은 외곽선, 회색 코어 안의 이름("CORE"), 열린 벽 안쪽을 따라가는 주황 둥근 점선(개구부), 주황 화살표, 굵은 점선 호, 검정 "OPEN" 글자, 번호·칼럼 없음. 빨간 펜 표시는 이 주황 강조색으로 옮긴다. 이름 붙이기는 코어를 "CORE" 로 쓰고, 스케치에서 읽은 화살표·호에는 말풍선을 기본으로 붙이지 않는다. 새 스타일을 기본으로 하고 도면용(흑백)도 고를 수 있다. 하단 범례·핵심 메시지는 켜야 보이고, 도형 안 이름 표시는 도형마다 정한다. 회귀 31건 통과.
- **열린 벽 표시가 도형 외곽선에 겹치게 요청**: 처음엔 AI 가 읽은 표시 구간을 그대로 쓰고 안쪽으로 9px 띄워 그려서 벽에서 떨어져 떠 있는 점선이 생겼다. ① 읽은 구간을 가장 가까운 외곽선(벽)에 붙이고 벽 길이 안으로 맞췄더니 점선이 외곽선을 따르긴 했지만, AI 가 읽는 표시가 짧은 조각들이라 모서리 근처에만 점선이 생겼다(실제 스케치는 벽 전체를 따라 눈금이 있음). ② 좌표 조각 대신 **도형마다 '열린 변(위·아래·왼쪽·오른쪽)'** 을 읽게 하고(비전 모델에게 더 쉬운 질문), 같은 벽에 붙은 조각이 벽 길이의 절반 이상을 덮으면 그 변 전체로 합치게 했다. 결과: 가로 판 왼쪽·아래, 세로 판 왼쪽·오른쪽·아래로 읽혀 스케치와 일치했고 점선이 외곽선을 따라 이어진다. 편집 패널에서 변별 체크, 벽에서 안쪽 간격(0 = 외곽선과 겹침), '가까운 벽에 붙이기'를 지원한다. 회귀 32건 통과.
- **학습 질문 답**: 결과물은 코드가 그리는 SVG 라 파인튜닝보다 참고 개념도를 스타일로 구현하는 것이 효과적이다. 손그림+완성본 짝을 모아 평가 세트로 쓰고 읽기 예시(few-shot)에 활용하는 방향을 제안했다.

**남은 한계(전체)**: 샘플이 손그림 2장뿐이다. 바람 방향·방위 이름은 AI 추측이라 직접 확인해야 한다. draw.io 내보내기(3단계)는 만들지 않았다.
