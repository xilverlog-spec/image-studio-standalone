# 2026-10-12

> 자동 일지 생성이 claude 로그인 문제로 멈춰서 직접 작성했습니다.

## 오늘의 목표
유료 API를 연결하기 전에 남은 일을 끝낸다. 조감도에서는 참조 이미지가 있을 때도 짧은 지시문이 나은지 확인하고, 다이어그램 만들기에서는 만들어 두고 연결하지 않았던 두 종류와 평면 라벨 겹침을 마무리한다.

---

## 1. 조감도: 참조 이미지가 있을 때의 지시문
**왜 필요한가**: 지난번에 참조 이미지가 없을 때만 짧은 지시문으로 바꿨다. 참조를 넣는 경우(레퍼런스 모드, 이지 다중 첨부)는 여전히 1,300~2,100자의 긴 지시문이라, 같은 방식이 통하는지 확인해야 했다.

**수정**: 참조용 짧은 지시문(`kontext_short_ref`)을 만들었다. "이미지 1은 원본, 이미지 2~는 참조"로 부르고, 참조에서는 표면(재료·리듬)·조명·주변만 가져오고 건물 형태는 가져오지 않는다고 한 문장으로 못 박는다. 참조별 역할·"가져올 것"·분석 요약을 생성 요청에 함께 보낸다. 사용자가 프롬프트를 직접 고쳤을 때는 짧은 지시문이 그 수정을 무시하지 않게 긴 방식으로 보낸다.

**시험**: 같은 시드로 긴/짧은 지시문을 비교했다.
- 1-1 공장 + 노출콘크리트(새로 제안 / 그대로 입히기): 두 결과가 눈으로 구분되지 않았다. 둘 다 콘크리트 외장은 약하게만 반영됐다. 멀리 있는 큰 건물에 작은 참조 사진을 입히는 조합이라 모델 한계로 보인다.
- ALT3 카페 + 적벽돌 참조(새로 제안): **긴 지시문은 참조 건물의 모양을 통째로 베껴** ALT3 대신 붉은 벽돌 3층 상자를 만들었다(형태 점수 0). **짧은 지시문은 ALT3의 곡선 매스와 지붕 루버를 지키고 벽돌색만 입혔다.**

**결과와 원인**: 긴 지시문에 참조 건물 묘사가 많이 들어가 모델이 그 건물을 그리는 쪽으로 끌려간 것으로 보인다.

**수정 후 재시험**: 참조 이미지가 있어도 짧은 지시문을 기본으로 바꿨다. 기본 경로로 참조 1장(적벽돌)과 2장(입면+재질)을 다시 돌려 둘 다 형태가 유지되고 재료만 입혀지는 것을 확인했다. 분석 요약이 문장 중간에서 잘리는 문제도 문장 단위로 자르게 고쳤다.

## 2. 다이어그램 만들기: 프로그램 버블도·층별 조닝도 연결
**왜 필요한가**: `program.js`, `stack.js`가 만들어져 있었지만 종류 목록에 없어 화면에서 쓸 수 없었다.

**수정**: 종류 목록, AI 프롬프트(스키마·규칙), 정규화, 글자 수정, 예시를 연결했다. "자동" 선택에서 AI가 4가지 종류(배치·매스·프로그램·조닝) 중 고른다.

**시험**: 실제 Gemini로 세 요청을 넣었다. 도서관 층별 구성은 조닝도, 문화센터 공간 관계는 버블도, 마을 광장 흐름은 기존 배치 개념도로 정확히 골랐고 모두 그려졌다.

**눈으로 본 문제와 수정**
- 조닝도: 층 칸의 이름이 칸 정중앙에 놓여 보이드·코어에 가려졌다(4F 라운지가 안 보임). → 칸에서 보이드·코어를 뺀 가장 넓은 빈 구간에 놓고, 좁으면 글자를 줄이거나 줄임표로 바꾼다.
- 버블도: 같은 묶음 안의 원이 붙어 연결선이 안 보였고, 연결이 많으면 라벨이 원 위에 얹히고 묶음 이름이 선에 가려졌다. → 묶음 간격을 넓히고 글자를 흰 테두리로 맨 위에 그리며, 짧은 선·원 위 라벨은 생략한다.
- **남은 한계**: 연결이 많으면 선이 다른 원을 지나가고, 라벨이 묶음 이름과 겹치는 곳이 한두 군데 남는다.

## 3. 평면 라벨 겹침
**왜 필요한가**: 평면 개념도에서 방 이름·구역 이름표·주석 상자가 서로 가렸다.

**수정**: 이미 놓인 라벨 상자를 기억해 겹치면 다른 후보 위치(위/아래, 좌우)로 옮기고, 방 이름은 글자를 줄이거나 비켜 놓는다. 끝내 못 놓으면 생략한다.

**시험**: 작은 방이 붙은 합성 평면으로 전후를 비교해, 이름표끼리 겹치던 것과 주석 상자가 이름표를 가리던 것이 해결된 것을 확인했다.

## 4. 손스케치 → 다이어그램 + 바로 고치기 (1단계 편집)
**왜 필요한가**: 설계자가 손으로 그린 개념 스케치(예: 판상형 + 맞통풍)를 정돈된 다이어그램 소스로 만들고, 화살표 표시·선 종류 같은 간단한 것은 바로 고쳐서 SVG로 받고 싶다.

**시험과 결과**: 지금 앱의 이미지 읽기에 넣어 보니 손스케치를 "방 7개짜리 평면도"로 읽어 없는 이름을 지어냈고, 판상형 띠와 물결선을 놓쳤다. 읽기 방식이 방 단위 평면도를 전제로 만들어졌기 때문이다.

**수정**: "해석하지 말고 그려진 도형을 있는 그대로" 읽는 손스케치 전용 읽기(상자·빗금 채움·자유 곡선)를 만들었다. 가까운 모서리를 맞추고 칸막이를 반듯하게 정리하며, 요청 문장을 얹어 이름·설명·바람 방향만 AI가 정한다(도형 위치는 못 바꿈). 번호 표식 + 우측 설명 칼럼으로 이름표 겹침을 없앴고, 바람은 굵은 띠 + 유입/유출 표시로 그렸다(처음엔 발표용·도면용 2종이었으나 사용자가 발표용은 필요 없다고 해서 도면용 하나로 통일).

**1단계 편집**: 구조(spec)를 코드가 그리는 방식이라 화면에서 요소를 클릭하면 속성(화살촉 방향, 실선/파선/점선, 굵기, 색, 글자, 위치)을 바꾸고 즉시 다시 그린다. 요소 추가·삭제, 방향 뒤집기, 되돌리기(Ctrl+Z), SVG·PNG 저장(저장본에는 편집용 속성을 넣지 않음)을 넣었다.

**재시험**: 브라우저에서 실제로 읽기→생성→클릭 선택→화살촉 양쪽→점선→뒤집기→되돌리기→화살표 추가·끝점 이동→글자 메모 추가·삭제→Delete 키→도면용 전환→SVG 저장까지 확인했다. 회귀 점검에 손스케치 렌더·편집 함수 6건을 추가했다(전체 22건 통과).

**참고 그림을 보고 선 표현 확장**: 사용자가 가져온 참고 다이어그램은 맞통풍이 S자로 휘어 창을 통과하는 부드러운 푸른 리본이고 벽에는 점선 캡슐(개구부)이 있었다. 우리 결과는 가는 선이 손떨림 그대로 구불거려 부자연스러웠다.
- **곡선**: 읽은 선을 Chaikin 으로 다듬어 9점으로 다시 뽑고(손떨림 제거), 곡선 모양(읽은 모양/S자/호/직선)과 세기·휘는 정도를 속성으로 조절하게 했다.
- **선 표현**: 실선·파선·점선에 일점쇄선, 이중선, 리본(끝이 가늘어지는 붓 띠), 번짐(끝이 흐려지는 그라데이션 띠), 화살표 반복, 물결 장식선을 추가했다. 기본은 리본이다.
- **개구부**: 점선 캡슐 도형과 범례를 추가했다.
- **시행착오**: 물결 장식선이 울퉁불퉁했다(중심선의 점에 붙여 계산해 계단이 생김) → 호 길이를 따라 보간하게 고쳤다. 화살표 반복은 끝 화살촉과 떨어져서 간격을 고르게 나눴다.
- **재시험**: 6표현 × 4모양 × 4화살촉 × 2스타일 전 조합과 개구부·길이 0인 선이 깨지지 않는지 회귀 점검에 넣었다(25건 통과). 브라우저에서 선 표현·곡선 모양·휘는 정도·개구부 추가·SVG 저장을 눌러 확인했다.

**남은 한계**: 샘플이 손그림 1장뿐이다. 바람 방향·방위 이름은 AI 추측이라 직접 확인해야 한다. 끌어서 옮기기(2단계)와 draw.io 내보내기(3단계)는 만들지 않았다.
